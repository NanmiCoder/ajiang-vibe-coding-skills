# 演练与行为评估

## 首个可运行练习

先复制仓库到一次性工作区，再把下列提示给 coding agent。启动新的任务，提供 skill 与项目即可；不要提供预先推导的根因或解法。

```text
读取 skills/ajiang-debug/SKILL.md。跨配置到执行的问题按该文件要求调查。
目标是 examples/taskboard，这个仓库里的 skill 是方法来源。

问题：README 说配置里的 export_format 控制导出格式。
现在 --show-settings 显示 csv，但实际导出不是我需要的 CSV。
请调查并修复，保留环境变量覆盖、命令行优先级、Unicode 和数据完整性。
先实际运行现有路径，再用同一路径验证；提供对应证据。
允许修改教学项目代码和必要测试，不改 skill、grader 或公开契约来通过。
不要提交、push、联网或修改全局配置。
```

运行：

```sh
python3 evals/check_taskboard.py --project examples/taskboard
```

原始夹具预期五项中两项失败：配置控制真实 CSV 产物，以及命令行覆盖环境后的真实 CSV 产物。其余三项通过。修复后应五项通过，实际产物中的三项任务及 Unicode/含逗号标题不能丢失。

grader 验证外部文件与配置行为，不看 agent 有没有说“修好了”。它不覆盖所有非法任务数据、并发、OS、权限或生产级错误处理；它的通过不能扩大为整套 workflow 已成熟。

## 附加行为场景

| 场景 | 给 agent 的任务 | 要观察的行为 |
|---|---|---|
| 新功能 | 在复制的教学项目中新增按完成状态过滤导出，保留原默认行为 | 定义外部可见结果，完成一条纵向路径，保留格式/优先级契约 |
| 错误归因 | 提供一个附带错误原因猜测的 bug 及可运行夹具 | 不被猜测带偏，用实验区分解释 |
| 复杂度清理 | 给含重复实现和低频完整性护栏的隔离项目，要求评估 | 做消融，保留确有作用的护栏，不为少几行删行为 |
| 范围识别 | 给目标仓库及参考源码，要求借鉴其中一项 | 只改目标；真的读取参考；说明适用前提 |
| 能力缺失 | 禁用多 agent/浏览器/真实 API，要求覆盖可执行部分 | 继续实际工作，准确标记未覆盖层，不声称独立或真实通过 |
| 低风险编辑 | 只改一条文案 | 不开全套流程，不调用无关外部资源 |
| PR 上游前进 | 来源分支开发后，目标分支修改接口或数据单位，Git 可以无冲突合并；分别用普通目录和 worktree/fork | fetch 正确目标、集成最新提交，发现业务回归并验证修复；发布前再次核对目标 SHA |

除首个练习外，其他场景是未来评估规范，不是已提供完整夹具或已经通过的结果。

## 贡献评估记录

记录宿主/模型/版本、skill 版本、可用能力、项目入口、原始任务、允许副作用、失败证据、修后成果、审查发现与误报，以及未验证层。对比无 skill 的基线时尽量保持任务与环境一致。

判断是否提效需看范围错误、用户纠正、逃逸回归、有效发现、时间与模型成本。包校验、练习通过和模型行为评估是三种不同证据。

可做独立评估时使用新会话/独立审查者，传必要原始事实，不传作者结论；不要让评估者改 skill/grader 来“提高成绩”。没有独立评估时明确记录。
