# 双 Agent 博弈

用两个立场相反的 Agent 制造最小有效摩擦，打破单一 Agent 的确认偏误，同时避免多人团队的 Token 爆炸与传话失真。核心原则：**只用双角、上下文隔离、两轮封顶、分歧转实证**。

## 先判断是否需要博弈

- **适合启动**：架构或技术方案有明显权衡、疑难 Bug 存在多个竞争假说、高风险改动需要攻防验证、重要重构担心遗漏隐含依赖。
- **不要启动**：路径明确的单步修改、普通信息检索、常规代码审查（直接用单 Agent 或 `ajiang-review`）。不要为了“看起来严谨”给简单任务套博弈流程。

## 固定双角与隔离原则

所有需要博弈的任务统一收敛为一对张力，不再拆出 3-7 个平行角色：

- **正方（立论者）**：给出主推方案、根因假说或实现路径，写明关键前提与支撑证据。
- **反方（挑战者）**：在**独立上下文**中运行，专门找反例、边界失败、隐含假设、维护成本与更简替代方案。
- **主 Agent（裁判）**：准备原始背景、控制轮次、核实双方证据并做最终拍板；不替任何一方脑补，也不按语气强弱判胜负。

隔离与防串通要求：

- 反方只接收「原始任务与约束 + 正方结论/改动」，不继承正方的推理草稿或情绪倾向，避免顺着正方思路点头。
- 博弈阶段默认只读，或各自在隔离位置跑验证，禁止两个 Agent 并发修改同一份正式源码。
- 使用当前环境提供的独立子 Agent / 委派能力，不限定客户端、模型或工具名。若当前环境不支持独立上下文委派，先明确说明限制，再按两阶段显式切换视角完成分析，不把单上下文自演说成独立双 Agent 博弈。

## 两轮收敛协议

### 第 1 轮：独立立论 → 定点挑刺

1. 主 Agent 先整理中立的任务背景（目标、约束、现状、相关文件或版本），不夹带结论。
2. 正方输出：结论、最小可行方案、关键依据与待验证假设。
3. 反方在独立上下文中审查，最多提出 **3 条最致命的反驳或风险**。每条必须写清具体触发条件、代码/数据路径或可证伪前提。找不到阻断问题就直接说明已检查范围并放行，禁止为了扮演反派凑数或纠结风格偏好。

### 第 2 轮：举证回应 → 裁判落地

1. 正方逐条回应反方的挑战：要么拿出代码路径、日志或实测证据反证，要么直接承认问题并修正方案，不强行辩护。
2. 主 Agent 核实双方关键论据并裁决：明确哪些挑刺成立并合入方案、哪些因证据不足或收益不成立被驳回。
3. **硬终止条件**：最多 2 轮交锋，禁止来回辩论。若第 2 轮结束后仍有核心分歧，不再继续“说理”，直接转成一个**最小实证检查**（跑定向测试、查真实日志、做隔离 PoC），用运行结果终结争论。

## 常见场景映射

| 场景 | 正方交付 | 反方主攻 | 裁决证据 |
|---|---|---|---|
| 方案 / 架构选型 | 主推方案、边界与迁移路径 | 过度设计、隐含成本、更简替代 | 约束核对、原型或基准数据 |
| 疑难 Bug 排障 | 主根因假说与复现证据 | 竞争假说、反例与逻辑漏洞 | 定向复现或对照实验结果 |
| 高风险改动攻防 | 实现方案与边界处理 | 并发/状态/安全/回归漏洞 | 真实调用链与失败复现 |
| 复杂重构 / 去重 | 统一后的目标结构 | 隐含调用方、平台或行为差异 | 引用追踪与回归测试结果 |

## 输出结果

交付时按顺序写清：

1. **最终决策与落地动作**：采纳的方案或结论，以及下一步具体改动。
2. **关键争议与裁决依据**：逐条列出反方挑战、正方回应、是否采纳及对应证据。
3. **未验证风险与边界**：明确哪些前提尚未实测、依赖什么条件。
4. **实际博弈方式**：说明是否使用了独立上下文双 Agent、轮次数，以及分歧是如何收口的。

复杂决策或多轮实证可用 [博弈裁决记录](assets/task-record.md) 保存交锋与裁决依据。
