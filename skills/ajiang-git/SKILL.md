# 提交代码与创建 PR

完成用户要求的 Git 操作，保证提交范围清楚、说明准确。提交、push、创建 PR 和合并分别遵循当前任务的授权。

## 检查改动

读取项目 Git 规则，检查当前仓库、分支、HEAD、暂存与未暂存差异，以及最近提交的风格。区分本次任务与已有用户改动，不自动 reset、clean、stash 或覆盖无关工作。

没有 Git 仓库时说明原因，不自行初始化。需要 push、PR 或合并时确认远程和目标分支，未指定且无法从项目规则判断的目标再询问。

## 验证并提交

运行与改动相关的检查，确保验证覆盖将提交的内容。脏工作区里其他文件影响结果时，必要时用隔离副本确认。

只暂存已核实的任务文件。同一文件混有无关修改时分离本次改动；无法安全判断归属时说明具体问题。不同目的的改动按需要分提交，避免为了整理历史而改写已有提交。

提交信息沿项目风格，简短描述实际变化；只引用真实 issue。提交后检查结果。hook 失败时修复相关原因后重新提交，不绕过检查。

## 推送或创建 PR

用户要求 push 或 PR 时，更新相关远程引用，确认提交基于正确目标。正常推送，不擅自 force push 或删除分支。

PR 标题与说明围绕最终问题和行为，附必要验证及未覆盖项，省略讨论过程和未实施方案。创建后检查真实 PR URL，不能把本地提交当成远程交付完成。

## 需要合并时

检查目标是否被其他 worktree 检出以及是否有未提交修改，按项目策略集成；不能硬改已检出目标的引用。仅合本次提交时，确认范围和依赖。

冲突按两边业务意图与验收条件解决，不能只选能编译的一边。有实质取舍无法判断时，给出具体冲突和选项。集成后验证受影响的原任务与相邻路径；无文本冲突不等于无行为冲突。

## 输出结果

报告完成的操作、提交 SHA、推送分支或 PR URL，以及未完成项。需要检查 CI 时确认实际结果，本地检查与远程 CI 分开报告。

多次提交或合并可用 [Git 操作记录](assets/task-record.md) 保存范围、版本和验证结果。
