# 美术方向：这支片子为什么好看

> 结论先说：**好看不是因为浅色**（第 3 期 v1 和 v3 色调几乎一样）。起作用的是这几条：
> - 真实产品画面当主角；
> - 主题从产品自己的美术长出来，并按这期的演出类型来做；
> - 全片一种镜头语言；
> - 镜头卡的调校动作换皮；
> - 字和主体够大，有“大片感”；
> - 多轮看帧。
>
> 下面逐条给证据，并说明能否迁移。

- **第 3 期**（ModelDial 模型检测上线，浅色产品功能演示）做了三版：v1、v2 被否，v3 用户回复“真的非常棒”。
- **第 4 期**（ModelDial 推箱子挑战赛，深色产品比赛横评）第一章做了四版，v4 被认可：“后续全部按这个做吧”，成片后用户回“做得太好了！”。

本文对照这几版和用户的每一句反馈，找出真正起作用的决策，再分清哪些能用到下一期、哪些只适用于 ModelDial。**动手前先做 §0。**

## 0. 先定主题：产品自己的美术 × 这期的演出类型（10 分钟内，写成 BRIEF 第 0 节的一句话）

从 CSS 抽出来的 tokens 只是颜色和字体，不等于主题。第 4 期 v1–v3 都用了产品 tokens，仍被否，用户原话：“完全没有那种大片的感觉”。v4 加上产品自己的舞台主视觉和转播式演出，交稿 3 分钟后被认可。

**第一步：盘点产品自己的美术**，找到就用，不要自己画：
1. 主视觉、舞台图、吉祥物或主持人立绘、游戏精灵图、产品自己的状态横幅和徽章：在产品仓库 `public/assets/` 或官网首页大图、OG 图里找。第 4 期用的是 `modeldial-arena/public/assets/acid/` 下的 `arena-sokoban.webp`（舞台）、`host-sokoban.webp`（主持人）、`arena-cube.webp`，以及 DEADLOCK / CLEAR 横幅的样式。
2. 产品自带的动画组件（游戏棋盘、表盘、回放器）：读源码，把引擎和渲染组件移植进 Remotion，用真实记录驱动，不要用录屏或截图冒充动画。用户原话：“推箱子的代码要动起来。本来我们就是用一些前端技术做动画嘛……你完全可以去复现出来”。
3. 字标、品牌 logo、CSS tokens（[assets §2](assets.md)）。

**第二步：判这期的演出类型**：

| 这期讲的是 | 演出类型 | 画面语汇 | 判例 |
|---|---|---|---|
| 模型比赛、挑战赛、排行榜、横评 | 电竞 / 体育转播 | 主视觉舞台铺底；选手登场；1ST / 8TH 记分牌；生命条、方向键 HUD、秒表；全屏死局横幅擦过；揭晓时翻牌 | 第 4 期 seg0 v4（`assets/examples/ep4`） |
| 产品功能上线、上手教程 | 产品演示（Screen Studio） | 真实页面推拉；取景框加编号标签；页面元素抬起讲完再放回 | 第 3 期 v3（`assets/examples/ep3`） |
| 原理、观点 | 编辑排版 | 大字标题卡 + 真实来源截图 + 能数的物件 | — |
| 其它 | 先找最接近的一种 | — | 第一章交给用户时写明“按 X 风格做的” |

**第三步：大片感检查**（第一章交给用户前逐条过；“克制”只管特效，不管画面尺度）
- [ ] 舞台不空：产品主视觉铺满 16:9 当远景，数据镜头里压到 45–55% 不透明度；不出现“纯黑底 + 中间一小块”。
- [ ] 字和数字够大：主标题 120–170px，关键数字 200–470px，逐句标题 58–64px。
- [ ] 实物有体积：棋盘、榜单这类“物件”带透视立在舞台上，再慢慢放平（第 4 期棋盘 rotateX 24°→9°，魔方榜 rotateY −18°→−7°）；表格、文字、思考记录保持正视。
- [ ] 每章至少一个产品原生的演出组件：HUD、记分牌、主持人、真实棋盘等。
- [ ] 口播点名的模型，画面上有它的 logo（图标 + 字标）。
- [ ] 数据都是真的，没有示意图表。
- [ ] 仍然没有粒子、我们自己加的发光、震屏（v4 一个都没用）。

**第 4 期被否的三种做法**（拼图在 `assets/examples/ep4/`）：
- v1：回放页截图推近 + 手画的“示意”死局格子，而且和口播无关。用户：“你的音频完全没有跟画面一起走”。
- v2：排行榜表格截图逐格推近，像在翻网页，还把第一名露出来了。
- v3：黑底匿名小卡、“1 点 = 1 分”的点阵示意、七段码数字，全章没有 logo。用户：“完全没有那种大片的感觉”“Logo 也没有用”“示意图那些写得感觉也很丑陋”。

## 1. 三版对照

| | v1 | v2 | v3（通过） |
|---|---|---|---|
| 做法 | 一个 agent 约 1 小时写完 9 段，用的是 video-mg-remotion 的字符串 HTML 引擎和 keynote 主题，品牌蓝换进去 | 深海军蓝舞台、体积光、镀铬大字、粒子爆炸、印章、震屏、22 个 Codex 生成的 3D 道具，4 个 agent 并行 | 产品自己的 CSS tokens、真实网页当主角、Screen Studio 式推拉；每章借一张 shotcraft 镜头卡并重新蒙皮；9 个 agent 并行，主 agent 验收 3 轮，另加独立审片 |
| 截图 | 推拉做得好（“截图放大那些都没问题”） | 截图缩成小窗、倾斜放进 3D，在深色舞台上像白色补丁 | 截图占满画面，推近到正在讲的那一块，MG 从页面元素里“长”出来 |
| MG | 浅灰底，白卡片，小字标签，动效只有淡入上移，像 PPT | 规则要求每页至少一个“爆点”、静止不许超过 1 秒，于是满屏特效 | 用产品自己的组件语言（发丝边白卡、胶囊、结论色），动效来自调校过的镜头卡 |
| 用户原话 | “你现在这个片子完全没有任何的美感……不像那种 AE 风格的视频” | “根据我们最原始的需求和我想达到的效果来看，现在出来的效果我非常不满意” | “真的非常棒，但是你要注意有一些二维码我们得打个马赛克” |

**关键的反直觉事实：** v1 和 v3 的静帧色调几乎一样，都是浅底、白卡、品牌蓝。所以 v1 失败不在配色，v2 用深色也不是在对症下药。三版真正的差别在**手艺密度**和**两套视觉系统是否打架**。

- v1 的问题是做得粗，不是选错了方向。字小，主体缩成一团，四周大片留白；每页都是“标题加几个框”；没有镜头语言；动效没有时值层次。
- v2 的问题是方向错了。用户说“像 AE / 很酷炫 / 有爆炸”，v2 把它当成了特效清单。用户真正要的是**像专业动效师做出来的那种质感**。而且参考片是 30 秒、跟着音乐走的发布片，这次是 6 分钟、跟着口播走的讲解片，片种不同（见 §4）。
- v3 保留了 v1 唯一被肯定的东西（截图推拉），把“质感”放在运动、构图和字号上，特效几乎为零，结果被认可。

## 2. 起作用的 7 个决策

### 2.1 视觉语言从产品自身取

- **v3 的做法：** `tokens.ts` 的每个值都来自 modeldial.com 的 `styles-base.css`，包括底色、墨色、品牌蓝、发丝线和字体 Geist。结论色取自用户报告卡上的“一致 / 相近 / 不一致”。
- **为什么好看：** 片子的主角是真实网页截图。MG 和截图用同一套视觉系统，截图就像片子本身的一部分，不会像贴上去的补丁。用户要求的“最后合起来大家是同一个主题”，靠的是这套共用的 tokens，而不是一个另造的“宣传片皮肤”。
- **能迁移的部分：** 方法本身。每期都从当期产品抽 tokens，具体做法见 [assets.md](assets.md) §2。浅色只是 ModelDial 恰好浅色，不是规律。深色产品就用深色舞台，但同样不加发光（见 2.4）。
- **tokens 只是一半：** 产品自己的主视觉、立绘、动画组件是另一半，见 §0。第 4 期只用 tokens 的 v3 被否，加上产品美术的 v4 通过。
- **反例：** v2 的配色（#060A1C 舞台、#4C7DFF 电光蓝、#5BE4FF 亮青）在产品里找不到出处。用户在另一个会话里把这种“深蓝科技光效”评价为“丑陋”。

### 2.2 真实网页当主角

- **用户原话：** “核心思想就是能去截图，能看到真实网页的一些效果……总之要把这个事情表达得很清楚。”
- **v3 的做法：** 9 段里有 5 段（报告、上手、Key 安全、为什么免费、结尾）以真实页面或用户自己的真实产物为主。另外 4 段讲原理和套路，也都至少落一处真实页面：seg0 的映射行、seg2 的探针原文、seg5 的手动模式、seg6 的页面免责声明（第二轮专门加的）。MG 只在两种情况下出现：
  1. 页面上没有的东西，比如原理示意、客户端终端；
  2. 从页面里“抠”出一块抬起放大（`Cutout`），把页面元素变成讲解对象。例如报告卡的散点图被抬出来逐点计数到“第 37 名”，映射规则那一行被裁出来推近。
- **为什么好看：** 真实界面本身就是信息量最大、最可信、设计最完整的画面，产品团队已经替你做好了设计。手搓的复刻永远不如原物。
- **能迁移的部分：** 只要选题里有可截的真实界面（产品、网站、仓库、文档、终端），就让它当主角。观众看完要能照着操作一遍（seg3 的逐字填表教程）。
- **ModelDial 专属的部分：** “报告卡 + 散点图”这类素材是这期碰巧有的。下一期要先盘点当期有哪些“真实产物”，比如报告、截图、结果页、数据，见 [assets.md](assets.md)。
- **不是每句都截图（第 4 期）：** 用户原话：“并不是所有的页面你都需要用实际的截图，你要去思考：讲到什么地方合适用截图放大……什么时候用MG动画这些”。
  - 讲过程（怎么走、哪步错）：用移植的产品前端动画，配真实数据。
  - 证明“页面上真这么写”：截图推近。
  - 讲跨对象比较：用产品风格的 MG。
  - 选法见 [chapters §3.5](chapters.md)。
  - 第 4 期 v2 几乎句句都是截图推近，被否。

### 2.3 Screen Studio 式推拉，而且全片只有一种镜头语言

- **v3 的做法：** 所有镜头都包在 `<Cam moves>` 里，示意图和卡片画面也不例外。
  - 推拉统一用一条曲线 `E.cam = bezier(.42,0,.18,1)`，起步柔、落位长；缩放在对数空间插值。
  - 单次推拉 0.9–1.3 秒，推到位后至少停 1 秒。
  - 讲到哪推到哪，讲完拉回全景。
  - MG 画面也有 6 秒内 z 1.00→1.04 的极慢漂移。
- **为什么好看：** 真实页面和 MG 用同一台“摄像机”，观众感觉不到两种素材在切换。“像真人在演示”就是这个意思：先给全貌，再推到正在讲的那块，讲完拉回，光标按真人速度移动。
- **硬限制：**
  - 信息密集的画面保持正视，3D 倾斜只给叙事镜头（shotcraft Q6）。
  - 不加手持抖动和震屏（Q3）。
  - 截图推近不能超过素材的分辨率极限（见 §3）。
- **页面补丁例外：** 把截图局部改成另一个状态（例如表单已填、弹窗已关）时，补丁颜色取截图真实像素，不走 tokens——它要和截图融为一体。
- **结构规则（第 3 期 seg0、seg6 返工后定的）：** `Cam` 里只放“被讲解的对象”。**正在被念到的标题和结论放在 Cam 外面的屏幕层**。否则镜头一推，标题就被画面上沿切掉，第 3 期的旧样板自己就有这个毛病。

### 2.4 克制的 MG：包装在运动里，不在特效里

- **用户原话：** “该有的动画效果、转场以及放大缩小都要很自然，不要过度包装，但该有的包装还是得有。”
- **“该有的包装”具体指什么**（全部来自 v3 的组件和镜头卡）：
  - 入场统一用 blur-slide：上浮、去模糊、淡入，0.5–0.6 秒，逐字或逐词错峰。
  - 批量元素的错峰越来越快，收尾静止 ≥ 0.5 秒（shotcraft R2）。
  - “落地”的小元素给一次轻微过冲 `E.back`；卡片用双层接触阴影抬起（element-body-moves）。
  - 取景框咬合时有一次弹簧过冲，再贴一枚机器标签（scanline-annotate-focus）。
  - 马克笔高亮、手写下划线、焦点框描边。
  - 计数器滚动，数字到点亮起。
- **全片禁用：** 粒子爆炸、冲击波、印章砸入、震屏、故障闪、镀铬字、体积光、霓虹发光、深色舞台上的白色截图、生成的 3D 道具图。禁的是**我们自己加的**特效：产品自己的主视觉、舞台图、立绘（自带灯光）、产品自己的状态横幅（如第 4 期的 DEADLOCK / CLEAR）可以整张用，它们就是主题（§0）。
- **光效：** 最多给一个主角一次，必须裁在圆角里，默认不用（shotcraft Q4）。
- **颜色：** 只有一个强调色。结论色（好 / 坏 / 相近）**只表示结论**，不当装饰。语气是“让你放心”的段落（比如 Key 安全）不用红色吓人。

### 2.5 统一的转场语法

- **v3 的 `Shot` 组件**只有 6 种转场，**按两个镜头之间的关系选，不按喜好**：
  - `none`：镜头内部的推拉自己完成衔接。最自然，优先用。
  - `fade`：同一话题换画面。
  - `left`：叙事向前推进。
  - `up`：换一个层级，比如从结论到原因。
  - `zoomIn` / `zoomOut`：走进去看细节 / 退一步看全局。
- **每章只用 2–3 种。**
- **淡化不交叉叠化：** 旧镜头在重叠窗口的前 50% 淡完，新镜头从 40% 才开始进。独立审片发现，两个字多的镜头交叉叠化时会出现半透明双重字。
- **段首段尾的握手：** 每段第 0.3–0.5 秒内容入场；最后 0.4 秒内容淡出到**同一张空舞台**；最后 2–4 帧必须是纯空舞台。这样 9 个文件首尾相接，接缝处是“内容离场 → 同一张舞台 → 内容入场”，看不出是分段文件。这个做法能直接迁移到任何分段交付的项目。

### 2.6 字号与安全区

- **用户原话：** “右上角只用留一个很小的头像区域作为安全区，底部留一点位置我放字幕，但是也不用特别宽，16：9的视频正常的文字就好了。”
- **安全区：**
  - 头像圆 `{x:1690,y:30,w:200,h:200}`，字幕行 `{x:360,y:966,w:1200,h:64}`，要读的字底边 ≤ 930（1920 设计坐标）。
  - 背景、窗口边缘可以穿过安全区，**画面永远铺满 16:9，不缩成小窗**。414 期的判例：“让你做 16:9，你做的什么格式啊？真的是太丑陋了”。
- **字号**按经过镜头放大后的**有效字高**算，不看代码里的 fontSize：
  - 想让观众读的字 ≥ 28px，小标签 ≥ 24px，眉标 ≥ 26px；
  - 标题 64–96px，结论大字 56–92px。
- **构图：**
  - 主体至少占画面宽度约 70%，不能缩成一小团、四周大片留白；
  - 也不能大到贴边、被裁：第 4 期审片发现推近后右侧生命条被裁、步数挤进头像圆。用户原话：“生效的画面应该是布局合理的 不要太小 也不要太大”；
  - 正在被念到的标题离上沿 ≥ 60px；
  - 截图推近时，标题下面不能压着页面字：标题区（y<150）给截图加一条从底色到透明的渐变压暗，或者取景下移。第 4 期 seg3/4/11/13 都出过这个问题。
- **为什么要强调：** 第一轮 9 个 agent 交上来的画面几乎**全部**偏小。agent 在 1920 画布上排版，再看缩小的拼图，天然倾向于把东西做小。第二轮主 agent 群发了一条通用规则，统一放大之后，画面才“饱满”。下一期把这条规则直接写进 BRIEF，不要等第二轮再改。
- **和 shotcraft Q11 的区别：** Q11 要求叙事字幕 ≥ 56px，因为它服务的是没有口播的宣传片，字幕就是旁白。这里有用户自己的字幕承担旁白，画面上的字只是补充，所以 28px 够用。但这也意味着**画面上不要再写一遍口播原句**，只写关键词和结论。

### 2.7 主角镜头卡：怎么选、怎么重新蒙皮

- **选法：** 每章找出这一段的**核心动作**，从 video-shotcraft 的 124 张卡里挑 1 张（最多 2 张）当主角。一种手法全片只当一次主角（shotcraft P4）。第 3 期的对应关系如下：

| 章节核心动作 | 卡 | 本期用法 |
|---|---|---|
| 两个东西看起来一样，其实不同 | `data/before-after-slider-scrub` | 拉杆扫过“真 Opus / 掉包”两份回答，肉眼看不出区别 |
| 结果出来，逐项指出关键信息 | `effects/scanline-annotate-focus` | 浅色版：四角取景框依次咬住报告卡的 4 个区块，贴机器标签 01→04（去掉了扫描光带的科幻感） |
| 几个选项里只有一个对 | `interaction/chip-grid-single-select-blackout` | 三种问法里选中“写随机数”，其余两个降到 18% |
| 表面在变，底层不变 | `typography/pill-slot-cycle` | 模型名在槽里换来换去，下面的分布图纹丝不动 |
| 多个来源汇成一个 | `ui-entrance/bezier-source-converge-merge` | 两个开源仓库沿曲线汇入 ModelDial |
| 切换模式 | `interaction/segmented-thumb-hero` | 推近分段控件，切到“手动检测” |
| 把一个东西拿起来单独讲 | `ui-entrance/element-body-moves` | Key 输入框带双层接触阴影离开页面抬起 |
| 抽样 / 比例 / 逐个揭晓 | `transition/card-flip-reveal` | 10 张请求卡逐张翻面：8 张真 Opus，2 张被掺 |
| 收尾点题 | `typography/marker-underline-title` | 马克笔划出“听诊器” |
| 从一个细节拉到全局 | `opening/crane-rise-reveal` | 首页“各厂商最高分”一行特写，起吊 3.4 秒到整页 |
| 品牌收束 | `outro/logo-shrink-wordmark-lockup` | 报告卡同款表盘环收成图标，字标逐字母滑入，定版 hold ≥ 1 秒 |

- **蒙皮规则：**
  - **照搬：** 卡的动作语法、时值配比、缓动、过冲次数、遮罩时机，以及“已知坑 / 命门”里的参数。demo 是 30fps，秒数 = 帧数 / 30。为了贴合口播，总时长可以压缩，但配比不变。比如 lockup 从 4.4 秒压到 3.4 秒。
  - **全换：** 背景、颜色、字体、材质，一律换成本期 tokens。卡里的暗场、霓虹、光晕、冲击波、颗粒全部去掉，残影只保留成运动模糊（透明度降到 0.1–0.2）。
  - **锚定：** 每个动作阶段都用 `say('segN','词')` 锚到口播上。
- **少碰高能卡：** 卡库里能量标“高”的卡（`slam-entrance-moves`、`impact-feedback`、`fracture`、`crash-zoom-punch`、`tear-streak-transitions` 等）属于发布片语汇。讲解型 B-roll 全片最多用 1 次，而且只给全片高潮。第 3 期一次都没用，照样被认可。
- **真实页面多的章节：** 主角是页面本身，镜头卡只当页面上的覆盖层来用，比如取景框咬合、抬起、圈选，不另起一个 MG 画面。

## 3. 截图清晰度的硬限制

- 推近后发糊，原因在素材分辨率，和镜头参数无关。
- 判断方法：用 4K 成片上每个源像素被放大的倍数来衡量：

  **倍数 = z × 窗口缩放 k × 2 / 截图倍率 dpr**

  ≤ 2 为清晰；≤ 3 可接受短暂停留；超过就要重截。
- 第 3 期的实测：
  - 2x 整页截图在 1560 宽窗口里（k ≈ 0.98），推到 z ≈ 2.2–2.8 时，端点行的有效字高约 26–31px，清晰度可以接受。
  - 用户给的报告卡是 1x 图（1200 宽），最多只能推到“源图 1px = 屏幕 1.55px”，再大 JPEG 就糊了，所以单块区域没法铺满全屏。
- 要推得更近有三种办法：
  1. 用 dpr 3 重截；
  2. 只对那个元素截 4x（shotcraft Q2）；
  3. 换成在页面坐标里放大的覆盖层：用 MG 把那一行大字重写一遍，再标明这行来自页面。

## 4. 片种决定能量曲线（v2 最根本的错误）

- **两支参考片的性质：** 用户给的两支（纸面→蓝图→全息的 motion reel，X 对 LinkedIn 的发布片）都是 20–30 秒、跟着音乐卡拍、每一拍都要有事发生的**发布片**。
- **这次要做的片子：** 6 分钟、跟着口播走、观众要听懂的**讲解片 B-roll**。
- **两者的区别：**

| | 发布片 | 讲解片 B-roll |
|---|---|---|
| 时间锚 | 音乐节拍 | 口播的词 |
| 特效能量 | 持续高，逐拍冲击 | 中低为主，少数峰值落在叙事高潮 |
| 画面尺度 | 大 | **同样要大**：主视觉铺满、大字大数字、实物有体积（§0 第三步）。第 4 期派单只写了“能量中低”，做出来的 v3 被否：“完全没有那种大片的感觉” |
| 停留 | 少于半秒 | 关键信息落定后 ≥ 1 秒 |
| 主角 | 品牌和形式感 | 内容和真实界面；产品自己的主视觉、主持人、HUD 可以当舞台 |

- **用户给参考片时的做法：** 按 shotcraft P2 处理：先逐帧拆成手法清单，**逐个手法判断要不要用**，不要把整支片子的风格当成全片的命令。比如参考片的“弹簧缓动”“硬边擦除”“每拍都有事发生”可以借来用在局部，“深海军蓝 + 镀铬 + 爆炸”不能整体照搬。

## 5. 哪些能迁移，哪些只适用于 ModelDial

| 能迁移到任何选题的 | 只适用于 ModelDial 第 3 期（下期要重新判断） |
|---|---|
| 视觉语言从当期产品抽取；一个强调色；结论色只表示结论 | 浅灰底 #F7F8FA、ModelDial 蓝 #345DE3、Geist 加 PingFang |
| 真实界面当主角；MG 只补页面没有的东西，或从页面里抠出来讲 | 报告卡、散点图、映射规则这些具体素材 |
| 一种镜头语言（Cam + E.cam），推到位停 ≥ 1 秒，标题放在 Cam 外 | 9 个章节的具体分镜 |
| 6 种转场按关系选，每章 2–3 种；段尾淡到同一张空舞台 | 第 3 期选的 11 张镜头卡 |

| 每章 1 张主角卡，动作语法照搬，皮肤全换 | 红色和琥珀色的语义（“掉包”“相近”）；下期按当期结论语义重新定义 good / bad / warn |

| 主题 = 产品自己的美术 × 这期的演出类型（§0） | 第 4 期的酸性绿舞台、Arena 主持人、推箱子精灵 |
| 交付前请一个干净上下文的 agent 独立审片 | |

**容易误学的一条：** 不能把“浅色 = 好看、深色 = 难看”当成规律。第 3 期 v2 难看的原因有三个：配色不是产品的，满屏发光特效，截图和舞台两套系统打架。第 4 期的产品本身是深色界面，就从它的深色 tokens 和舞台主视觉出发做深色舞台，没有加我们自己的发光和粒子，被认可。

## 6. 两期成片实测（拆解结论，同类选题不用再派 agent 去拆）

**第 3 期**（浅色产品功能演示，`3期-Modeldial上线模型真假检测功能/` 成片）：
- **画面类型：** 真实截图推近 44%、手搓 MG 49%、标题卡 7%、录屏 0。按章节交替：讲原理的章以 MG 为主，讲证据和操作的章以真实界面为主。
- **怎么选画面：**
  - 句子里有“这里 / 点 / 填 / 切换 / 报告上写着”：真截图推近，加光标、打字或换状态。
  - 念结论：结果卡分块推近，加四角取景框、编号机器标签（标签字就是口播词）、焦点外蒙层。
  - 页面字太小：抠出来抬起放大，或在旁边叠一张大字复述卡。
  - 原理、机制、因果：用产品同款组件做 MG。
  - 数字、比例、次数：做成能数的物件（翻牌、条码）。
- **推近档位：** 整页 1.1×、区块 1.5–1.7×、控件 2.0–2.2×、主角微交互 4.4×（用矢量复刻接管）。位图最多 1 源像素 ≈ 1.55 屏幕像素。
- **节奏：** 画面明显变化的中位间隔 2.6 秒；焦点静止中位 1.4 秒。推拉 0.9–1.3 秒，提前 0.2–0.7 秒起步，落在关键词上。标题在关键词前 0.10–0.25 秒逐字出。
- **转场：** 横推约 10 次、柔切约 8 次、上推 5–6 次、推入 3 次、拉出 1 次。段与段之间：淡出 → 空舞台 → 入场。
- **标题字号：** 标题卡 92–112、常规 60–76、眉题 24；每句只把一个词组染强调色。
- **不足：** 同一表单演示了三次；有几处 0.5–1 秒空屏；有连续 40 秒都是“眉题 + 标题 + 卡片”，像模板。

**第 4 期**（深色比赛横评，`4期-推箱子挑战赛/素材/口播精剪/B-roll成片/`，源码 `assets/examples/ep4`）：
- **第一章 v4 的配方：**
  - 产品舞台图铺满全屏；
  - 170px 大标题；
  - 真实棋盘带透视立在舞台上，用真实回放驱动，第 7 步推死时全屏 DEADLOCK 横幅擦过；
  - 方向键 HUD、生命条、秒表；
  - 主持人立绘入场；
  - 真实魔方榜（前几期的榜，可以露）；
  - 8×6 真实战绩矩阵，名字用 ???；
  - logo 老虎机停在“?”；
  - 巨大的 91.6 和 0。
- **画面类型：** 真实动画（移植的棋盘）为主，截图推近负责“证明”（思考原文、裁判提示、榜单），MG 记分牌负责比较和花费。

  - 段首亮背景硬切；
  - 空舞台超过 1 秒；
  - 数字挤进头像圆；
  - 口播“七八十分”和同屏的 99.6 矛盾。
