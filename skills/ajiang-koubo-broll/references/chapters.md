# 分章节

章节同时是三样东西：**叙事单元**（观众心里的一个问题被回答）、**交付单元**（一个 MP4，文件名带 SRT 起止）、**工作单元**（一个 agent 负责）。三者对齐，才能并行做、单独改、单独重渲。

## 1. 读懂

```sh
python3 $S/scripts/init_project.py list --srt 精剪.srt      # 条号 | SRT 起点 | 时长 | 文本
```

通读全部字幕和稿子，先写 200 字以内的理解：这期要让观众相信什么、带走什么、有哪些真实页面或真实产物能证明。

再列一张**勘误 / 口径表**：精剪时存疑的专名，口播和稿子或页面不一致的数字。例：
- 第 3 期：口播“快破 700 万”，首页是 7,484,698；“GPT-5 的 Luna”是推测写法。
- 第 4 期：口播“七八十分”，魔方榜是 86–99.6；口播“排到第三”，榜上是第 2。

这些进 BRIEF 第 5 节和交付说明的“需要你看一眼”，**不阻塞制作，也不问用户**：画面跟口播走（§3.5 第 4 条）。用户原话：“说法以我的那个口播为准吧”。

## 2. 怎么切

1. **一章回答观众的一个问题。** 先把稿子拆成观众会问的问题序列。第 3 期 9 章：怎么被掉包的 → 检测怎么露馅 → 为什么随机数能抓 → 怎么用 → Key 安不安全 → 更隐蔽的掺水 → 工具的边界 → 为什么免费 → 去试试。
2. **切在话题转折那句的开口处。** 口播里的转折词就是刀口。第 3 期 9 章的起句：「但是好玩的事情来了」「为什么问它你是谁」「我们把开源社区里面…」「大家最关心的肯定是这个」「不过聊到这儿」「反过来」「最后可能还有朋友好奇」「感兴趣的朋友你可以现在去试一试」。用字幕条号写 `start`，不切在句中；一句话横跨边界就把边界挪到下一句开头。
3. **20–55 秒一章。** 短于 15 秒并进相邻章（一个 agent 起步要读几万 token 的 lib、样板和卡，太短不划算）；长于 60 秒拆开（第 3 期最长的 seg3 53.4 秒，做了 3 个镜头、其中一个 35 秒的一镜到底，已经接近一个 agent 能精修的上限）。6 分钟口播一般 8–10 章。**章数不设上限**：长片多出来的章不是问题，机器负载靠“同时跑的 agent ≤ CPU 核数 / 2，多的排队补派”控制（[orchestration.md](orchestration.md) §11）。`init_project.py` 对 <15s 或 >60s 的章会警告。
4. **整片覆盖，首尾相接。** 第一章从 0 帧开始，最后一章到母版最后一帧，中间无空档无重叠，用户只要按序号拖进剪映。`init_project.py` 自动保证；一条字幕归它**开口帧**所在的那一章（第 3 期旧脚本按毫秒取整，把第 114 条同时算进 seg4 和 seg5，文件名写成「字幕99-114」「字幕114-139」，新脚本已修，seg4 变成「字幕99-113」）。
5. **标题 4–8 个字**，说清这章讲什么，会进文件名：`{序号}_{标题}_{SRT起}~{SRT止}_字幕{a}-{b}.mp4`。

写成 `chapters.json`：

```json
[{"title": "开场模拟掉包", "start": 1, "brief": "映射规则那一行 + 客户端问它是谁"},
 {"title": "检测报告露馅", "start": 23, "brief": "真实报告卡：不一致 → 最接近 deepseek → 64 个里排第 37"}]
```

`start` 也可以写 `"f12445"`（帧号）或 `"00:03:27,417"`（SRT 时间）。改了章节就重跑 `init_project.py`（会重写 timing / 入口 / 口播切片，不动已写的段）。

## 3. 每章写什么（进 BRIEF 第 8 节）

```
**seg1 检测报告露馅（38.5s）** 主角卡：`effects/scanline-annotate-focus`（浅色版：四角取景框依次咬合报告卡关键区块并贴标签，去掉扫描光带）。
节拍：① 把掉包接口填进检测页（真实页面 det-api → det-filled，光标点开始）② 不问身份，只让它写随机数
③ 报告卡出来，推近表盘「不一致」→「最接近 deepseek-v4.1-flash-1017」④ 散点图抬起：64 个型号里排第 37，前三候选没有 Opus。
归属：完整拥有「报告卡逐块讲解」；「填表 → 点开始」只 2–3 秒粘贴带过（完整教学归 seg3）。
事实：选「三次探针」，和报告卡上的“已分析 3 次探针”一致。
```

- **节拍 3–6 个**，每个对应一句或几句口播：讲到哪句、画面是什么、用哪张真实素材。是方向，不是死命令。
- **主角卡 1–2 张**：`python3 $S/scripts/list_cards.py 对比 报告 翻牌 …` 按关键词挑。按“这章最难讲清的那个信息”选；一种手法全片只当一次主角。
- **真实素材**：文件名、要推近的位置；隐私裁切范围写死（“只能用 Cutout 裁 y1360–1425 那一行”）。
- **不做示意图表**：有真实数据就用真实数据（真实回放、真实榜单、真实战绩）。页面上不存在的纯概念，用产品原生物件来演，比如第 4 期 seg8 的“重开”按钮、生命条。第 4 期 v3 的“1 点 = 1 分”点阵被否：“示意图那些写得感觉也很丑陋”。
- 开头一章立住全片的主题和大片感（[art-direction §0](art-direction.md)）；最后一章以产品字标 + 网址定版，停 ≥1 秒，最后 0.4 秒淡到空舞台。

## 3.5 主题怎么落到脚本：分完章、写 BRIEF 之前先定四张表

第 4 期这四张表是被用户纠正了三轮之后才补进 BRIEF 的。下次开工就写，第一章动手前定好。

**1. 主旨一句话 + 悬念揭晓表。**

先找出开场里卖关子的句子（“最强的模型……”“垫底的模型……”），再写清：藏什么、在哪章哪句揭晓、揭晓前怎么处理、哪些照常放。

| 藏什么 | 哪章哪句揭晓 | 揭晓前怎么处理 | 照常放的 |
|---|---|---|---|
| 本期垫底是谁（Grok 0 分） | seg8 段尾“它是拿了 0 分” | 匿名记分牌，身份位用 logo 老虎机停在“?” | 前几期的魔方榜（名次、logo、分数都能放） |
| 本期第一是谁（Claude 91.6） | seg11 段尾 | seg11 之前不放带总分或名次的本期榜单 | 单关的通关、死局、步数 |
| 花费 | seg12 | 之前不出现美金数（截图里的也要压暗） | 参赛阵容和 logo（seg1 口播就点名了） |

要点：
- 悬念只藏**本期的名次和身份**。用户原话：“你不要具体的排名，但是可以讲上期模型魔方的时候那些排行榜，对不对？魔方又没有关系”。
- 匿名不等于去掉 logo，也不等于示意图：数据照样用真的，只把身份位换成“???”或停在“?”的 logo。
- 揭晓时复用开场的同一个组件，观众才有“悬念被回收”的感觉：第 4 期 seg0 的 8TH 记分牌在 seg8 翻面。

**2. 逐句镜头表**（`work/shotlist.csv`，主控写，章节 agent 只读）：`字幕号 | 口播关键词 | 画面形态 | 素材键 | 卡`。

每句口播一个画面落点，形态按这句在讲什么来选：

| 这句口播在讲 | 用什么 | 素材键示例 | 第 4 期的例子 |
|---|---|---|---|
| 怎么走、哪一步错了、谁通关了（产品自己用前端画的东西） | 产品前端动画的移植版 + 真实回放数据（4K 不糊，能慢放、定格、倒带，能卡在口播上） | `anim:L1/MiniMax/机会1` | `SokoBoard`：seg0 第 7 步推死；seg7 GPT 第 34 步定格圈注 |
| “这里 / 点 / 填 / 页面上写着”，要证明是真的 | 截图推近到那一格 + 取景框标签，停 ≥1 秒；推近后字还小于 28px，就抠出来放大，或在旁边用大字复述 | `st/trace-grok.jpg#原话` | seg4 Grok 思考原文分三档推近 |
| 怎么用、点哪里 | 录屏帧序列，或截图 + 光标 | `rec/op-versus` | seg13 人机对战 |
| 跨对象比较、规则、分值、花费 | 产品风格的 MG（记分牌、格子、条形图），只用口播说过的真实数字 | `mg:花费条` | seg0 8×6 战绩矩阵；seg12 花费条 |
| 还没揭晓的身份 / 名次 | 真实数据 + 匿名身份位 | `mg:身份位` | seg0 1ST / 8TH |
| 页面上没有的概念 | 产品原生物件来演（按钮、棋盘、生命条），不画示意图表 | `mg:重开按钮` | seg8 |

用户原话：“并不是所有的页面你都需要用实际的截图，你要去思考：讲到什么地方合适用截图放大，用 Screen Studio 的时候什么地方适合去做素材……什么时候用MG动画这些”。

- **同一个素材键只能归一章完整演示**，其它章只能 Cutout 那一行，或 2–3 秒带过。用镜头表直接生成 §4 的镜头归属表。
- 第 4 期就是在这里出了两条“严重”，都是 BRIEF 第 9 节把同一素材写给了两章：
  - “MiniMax 第 1 关第 3 步推死”同时派给了 seg2 和 seg4；
  - 魔方榜整页同时派给了 seg0、seg3、seg10。

**3. 每章一个主角镜头。** 从本期选好的卡里给每章配 1 张，全片每张卡只当一次主角，写进 BRIEF 第 9 节的节拍。以真实物件为主的章节（两盘回放并排、思考记录截图）可以只把卡当覆盖层。

**4. 口径表 + 用词表：以口播为准。**
- 口播和数据有出入时，画面跟口播走：不改稿，也不问用户。
- 画面里不能露出和口播矛盾的数字：裁掉或压暗那一列，或者换个取景。第 4 期例：
  - seg10 口播说“第三”，榜上是第 2 → 裁掉名次列；
  - seg0 口播说“七八十分”，魔方榜上是 99.6 → 应该把分数列压暗（第 4 期漏了，审片判为“中”）。
- 出入清单只放进交付说明的“需要你看一眼”。
- 用词表：同一种状态全片只用一个词，并且和网站原样一致。例：“超时 / 调用失败 / 安全拦截”。

## 4. 镜头归属表（第 3 期没做，审片才发现重复）

列出全片会反复出现的页面状态、交互和数字，每项只归一章完整演示：

| 页面状态 / 交互 / 数字 | 完整演示归 | 其它章怎么用 |
|---|---|---|
| 填 API 地址 + Key → 点开始 | seg3（逐字填表教学） | seg1 粘贴式 2 秒带过；seg4 从“已点开始”切入 |
| 复制提示词 → 粘进对话 | seg3 | seg5 只推近手动模式切换和提示词原文 |
| 报告卡 | seg1（逐块讲） | seg8 只推近“域名已打码”那一行 |
| 首页访问量 | seg7（“700 万+”卡片盖住精确数字） | 其它章取景避开精确数字 |

规则：
- 同一个页面状态第二次出现时，换角度或只给 2–3 秒；同一个数字全片一个口径。
- 第 3 期审片抓到：“填表 → 点开始”在 seg1、seg3、seg4 演了三遍；seg3 和 seg5 都演了粘贴提示词。第三轮返工了两段。
- 第 4 期审片抓到：MiniMax 第 1 关推死的回放在 seg2、seg4 各放了一遍；魔方榜整页出现了 3 次。第二轮返工了 3 段。
- 放在 BRIEF 里提前分好，比下游多一轮便宜。§3.5 的逐句镜头表写了素材键，就能直接查重。

## 5. 主角卡怎么对应（第 3 期的分配，可直接复用对应关系）

| 这章要讲的 | 卡（video-shotcraft） | 其它候选 |
|---|---|---|
| 两样东西看起来一样，其实不同 | `data/before-after-slider-scrub` | |

| 几种做法里只有一种行 | `interaction/chip-grid-single-select-blackout` | |
| 名字换来换去、本质不变 | `typography/pill-slot-cycle` | |
| 多个来源汇成一个产品 | `ui-entrance/bezier-source-converge-merge` | |
| 切换模式 | `interaction/segmented-thumb-hero` | `cursor-flyover` |
| 把一个元素从页面里拿起来讲（强调安全 / 重要） | `ui-entrance/element-body-moves` | |
