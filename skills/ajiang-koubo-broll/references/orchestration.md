# 编排协议：主控、章节 agent、审片 agent

> 用户点名的第 4 件事：agent 之间怎么通信、主 agent 怎么和子 agent 交互。提示词原文见 [prompts.md](prompts.md)。

## 0. 消息流（一页看懂）

```
主控：建工程 → 采素材（入库即扫码）→ tokens + 产品美术 → 四张表 → 2 个分析 agent（选卡 / 拆上期）→ 亲自做第一章 seg0 → 停，用户确认一次
  → 第一章组件进 lib + 整段压测 → BRIEF → 派发前检查单
  │  一条消息里并行发 N 个 Agent（通用 agent，后台）            ← prompts.md §1
  ▼
章节 agent ×N：读 BRIEF / lib / Seg0 / timing / 主角卡 → 写 SegN → still 自检 ≥3 轮 → preview → 最终回复（五块回报）
  │  task-notification（结果 = 它的最终回复）
  ▼
主控：Read final-sheet → 代存回报 out/reports/ → 记问题；台账 ledger.py
  │  全部到齐：tsc + 首尾帧拼图 + 跨章去重
  │  SendMessage(to=agentId) 第 2 轮定点修改                    ← prompts.md §2
  ▼
章节 agent：改 → 重出 final-sheet + preview → 回复 ≤100 字
  ▼
主控：预览全部重渲 → 起独立审片 agent（干净上下文）           ← prompts.md §3
  ▼
审片 agent：抽帧联系表 → 问题清单（严重/中/轻，带秒数和改法）+ 保留清单
  ▼
主控：共性问题等全员停下后改 lib → SendMessage 第 3 轮（开头说 lib 改了什么）→ 抽查 → 隐私第二道 → 预览页 → 停，等用户
      （用户说过“不要问我了”就不停：验收过一段就进 4K 队列 queue.sh → check → 隐私第三道 → deliver）
```

**一条最容易犯的错：对子 agent 只转述用户真说过的话。** 样板是主控自己定的，就写“主控定的”；用户没看过就别写“用户认可这个方向”。第 3 期 v2 的四份派单都写了“主控做的，用户认可这个方向”，用户其实没看过，4 个 agent 照着错方向各做了约半小时，整版被否。

**也不要替用户加码。** 派单时用户原话逐字放进引号，自己的推断另起一行，写成“总控推断：…”。分析 agent 回来的建议，先对照主旨和悬念表再用。第 4 期主控把“别把模型名称露出来”写成“不露名称和 logo”，又加了一句“能量中低”；选卡 agent 据此建议“第一章禁止选手面板、名牌、品牌色”，v3 照做后被否。

用户原话：“完全合理地利用 SubAgent 去干活呀。你其实完全可以自己当领导，让别的 SubAgent 帮你去干活……把它分配好。”以及“你用多个 Agent 去协调，每个负责一个章节，最后合起来大家是同一个主题。”

## 1. 为什么这样分工

- **上下文装不下。** 第 3 期 v3 每个章节 agent 第一轮就用了 25–33 万 token（读 BRIEF、读 lib、读镜头卡和 demo、看十几张拼图）。一个 agent 串行做 9 章，中途会被压缩好几次，前面的约定会丢。
- **墙钟时间。** 9 章并行，第一轮 22–33 分钟全部交齐；串行要 4 小时以上。
- **统一性不是靠一个人做，而是靠共享的东西。** 同一个 `src/lib`、同一份 tokens、同一个风格样板、同一份 BRIEF、同一套量化标准、每种镜头卡只给一章。这些在派发前就绪，agent 才会“像同一个人做的”。v2 只给了一个样板场景和一份 BRIEF，组件库还在边做边修，4 个 agent 各自写了一套局部工具（`WC`、`WD`、`SB2`），合并时要逐个查全局变量冲突。
- **主控不写章节内容。** 主控的上下文要留给全局：跨章去重、事实口径、声音、渲染、和用户沟通。主控只写第一章（seg0，即风格样板），和最后的小修（改一张图、调音量）。

## 2. 角色与文件所有权

| 角色 | 数量 | 可写 | 只读 | 不许做 |
|---|---|---|---|---|
| 主控 | 1 | `src/lib/` `src/data/` `src/index.tsx` `src/entries/` `src/segs/Seg0.tsx` `src/segs/seg0/` `src/segs/Sample.tsx` `scripts/` `public/{st,logo,fonts,sfx,audio,gen}` `BRIEF.md` `preview/` `out/reports/` `out/ledger.json` | 全部 | 写章节内容；在一轮进行中改 lib 的画面行为；对子 agent 编造用户的态度 |
| 章节 agent | 每章 1 个 | `src/segs/SegN.tsx` `src/segs/segN/**` `public/segN/**`（自己裁的图）`out/qa/segN/**` `out/preview/segN.mp4` `out/bundle-segN/`，临时文件放 `out/tmp/segN/` | 其余全部 | 改 lib/别的段/scripts；发布 Artifact；跑 ego-browser 或联网截图；写报告类 .md；渲整段 4K |
| 审片 agent | 1 | 自己的临时目录（`out/review/` 或 scratchpad 子目录） | 全部 | 改任何工程文件；继续委派 |
| 采集 agent（可选，第一章前） | 1–2 | 自己的 staging 目录（如 `../broll-work/cap-a/`），主控审完再并入 `public/` | 全部 | 进设置页、API Key 页、私人后台；截 ego-browser 光标浮层。回报里附“页面和口播对不上的地方”清单 |
| 分析 agent（第一章前） | 1–2，各 ≤15 分钟 | 不写文件，只在最终回复里给结论 | skill 范例、上期成片、video-shotcraft | 替用户定方向；它的建议主控要对照主旨和悬念表复核 |

为什么是“一个工程 + 分文件”而不是“每人一份副本”：副本要合并、lib 修复要逐份拷、共享路径会互相覆盖（v2 成员 B 的 `qa.sh` 被成员 A 的同名脚本覆盖，误跑了 A 副本的构建）。同一个工程靠三件事隔离：

1. **每段独立入口** `src/entries/segN.tsx`，`still.mjs` / `preview.mjs` 只打包这一段——别人写到一半的语法错误不影响你。
2. **每段独立打包目录** `out/bundle-segN/` 且 `enableCaching:false`——9 个 webpack 进程不共用缓存（这是派发前预防性加的，本期没有实际撞到缓存冲突）。
3. **（可选）git 快照**：`init_project.py --git` 建库；派发前、每轮收齐各 commit 一次；`python3 $S/scripts/ledger.py --project $P audit` 列出本轮改动并标出落在主控区域的文件，越界就 `git checkout -- <文件>` 回滚。这是预防：第 3 期 v3 没有 agent 越界，git 只是便宜的保险（注意它会把截图也提交进去）。

## 3. 派发前检查单（缺一项就别铺开）

- `npx tsc -p .` 全绿；每段有占位 `SegN.tsx` 和独立入口（init 已生成）；`public/audio/bgm-segN.wav` 至少是静音占位（init 已生成，否则 agent 第一次跑预览就 404）。
- `src/data/timing.json` 逐字命中率 ≥80%（第 3 期约 90%），抽查 3 个 `say()` 和口播对得上。
- `src/data/tokens.json` 已是本期产品的（没有 `_default`）；`meta.json` 的 `safe` 是本期头像 / 字幕位置。
- `src/data/pages.json` 登记了所有网页截图（尺寸、地址栏文字、元素坐标、一句话说明）。
- **隐私第一道已过**：`mosaic.py --scan` 无未处理命中，人眼看过每张截图；后台 / 个人数据没进库；需要隐藏的名字只留可裁的那一行（写进 BRIEF 第 3 节）。
- 第一章 `Seg0.tsx` 已经按 [qa.md](qa.md) §1 自检两轮，**用户已经确认过**；BRIEF 第 0 节逐字写了用户的认可原话。
- 第一章新写的组件已收进 `src/lib`，并**整段压测过**：渲一段 ≥40 秒的预览，加一张各种状态的静帧拼图。第 4 期 lib 只在 seg0 里验证过，第一轮被 agent 报出 5 个 bug：推箱途中闪红框、死局类型显示成“其他”、主动重开显示红色 DEADLOCK、`stateAt` 提前扣命、`Lines` 新旧标题重叠；还有一次 `Page crashed`。
- BRIEF 有四张表（悬念揭晓、逐句镜头表、口径、用词），每个素材键只归一章；BRIEF 第 8 节写了环境坑（不用 `rm -f $D/*.jpg`、ffmpeg 没有 drawtext、macOS 没有 `timeout`）。
- `BRIEF.md` 已写完，含镜头归属总表、口径表和本期结论色语义；派单里**没有替用户表态的话，也没有替用户加码**。
- `out/ledger.json` 建好（`ledger.py set …`）；用了 `--git` 的话 `git commit -m 派发前`。
- 声音工作和 4K 渲染不和第一轮抢 CPU：主控这时只做配乐、音效、写预览页这类轻活。

## 4. 派发

- 用 Agent 工具，`subagent_type` 用默认的通用 agent（general-purpose）。**不要用 fork**：fork 会继承主控整段上下文（几十万 token 的素材讨论），既浪费又会把主控的偏见带进去。
- **一条消息里同时发出全部章节 agent**，它们才会真正并行。`description` 写“segN 章节标题”，方便看通知。
- 提示词 = [prompts.md](prompts.md) 的「第一轮」模板填空。共性规则都在 BRIEF 里，提示词只写这一章的差异；不要把 BRIEF 内容抄进提示词（两处不一致时 agent 会挑一个）。
- 派完立刻记台账：`python3 $S/scripts/ledger.py --project $P set segN agent=<ID> round=1 status=working`（只收 `key=value`，写成 `--status done` 会被拒）。ID 在 Agent 工具的返回里（“agentId: …”）。这个 ID 只在内部用，不要贴给用户。
- 章节数超过并发上限时（见 §11），先派前 A 个，每收到一个“第一轮交稿”的通知就补派一个排队的章节，排队的标 `status=queued`。

## 5. 章节 agent 一轮里做什么

按提示词的顺序：读 BRIEF → 读 lib 全部源码 → 读样板 → 读本章字幕（timing.json）和稿子里的【画面】提示 → 读主角卡全文和 demo TSX 全文 → 写 `SegN.tsx` → 静帧自检 ≥3 轮（每轮看入场中、动作峰值、落定后；推近处 `--scale=1` 看清晰度）→ 渲一次带口播的预览，按口播关键词抽帧核对音画 → 回报。

主控对它的要求只有结果：能编译、能渲、拼图覆盖每个镜头、预览带口播、回报完整。怎么拆镜头、写多少私有组件由它决定。

## 6. 回报协议（子 agent → 主控）

- **只在最终回复里回报，不写报告文件。** 子 agent 写 `report-segN.md` 这类报告文件会被 harness 拦截；第 3 期 9 个 agent 都撞了一次、在回复里请主控“代存”。现在的模板不再要求写报告文件。
- 第一轮回报固定五块，便于主控扫读和转录：
  1. 交付文件路径（代码、私有目录、final-sheet、预览）。
  2. 镜头表：每行 `起–止秒｜画面一句话｜转场｜主角卡或真实素材`。
  3. 自检结论：对照 BRIEF 量化标准逐条 ✓/✗，不达标的写实测值。
  4. 遗留问题：自己没解决的、需要主控拍板的（例如“示意逻辑能不能用”）。
  5. 对 lib 的需求：缺什么、自己在私有目录里怎么绕的。
- 修改轮的回报 ≤100 字：改了哪几条、实测值。
- 主控收到后落盘：`out/reports/segN-r1.md`（主控写文件不受限），镜头表转录进 `work/preview.json` 的 `beats` 给预览页用。

## 7. 收稿：处理任务通知

每个章节 agent 停下时会来一条 `<task-notification>`（`status=completed`，`<result>` 里是它的回报）。同一个 agent 每被 SendMessage 续派一次，结束时就再来一条，task-id 不变。收到后按这个顺序做：

1. `ledger.py --project $P set segN status=done round=K`。
2. 用 Read 看它的 `out/qa/segN/final-sheet.jpg`（只看这一张拼图，不要逐帧翻）。
3. 落盘回报，记下要改的点（本章的 / 跨章的分开记）。
4. 给用户一两句进度：“seg2 交稿了，真页面推近和分布图都清楚。还剩 5 段。”
5. 第一轮：**等全部到齐再统一出第二轮**——跨章问题（重复镜头、全片字号标准、谁保留完整教学）要看齐全部才能定。第二轮起：哪章回来就验哪章，有问题立刻续派。

不要做的事：读 agent 的 output 文件（那是完整 JSONL 记录，会撑爆上下文）；在通知到达之前对用户描述它“做得怎样”；对一个仍在运行的 agent 重复派同样的活。

**巡检，不要空等。** 第 4 期 seg8、seg12 第一轮各用了约 6.5 小时，实际只干了 22–24 分钟：都卡在一条 `rm -f $D/*.jpg` 上（推断是权限确认框，用户在睡觉）。主控从 02:14 空等到 07:55。

规则：
- 派发后，用 `run_in_background` 起一个后台闹钟，例如每 30 分钟检查一次 `out/qa/segN/` 和 `src/segs/SegN.tsx` 的修改时间。
- 某个 agent 超过 30 分钟没有新产物，就查它最后在跑什么命令：用 `ps` 看它的 node / ffmpeg 进程；需要时从 `~/.claude/projects/<项目>/<会话>/subagents/agent-<id>.jsonl` 读最后几行，只读尾部。
- 卡住了就 TaskStop，用接手模板（prompts §4）重派。

后台 Bash 任务（Codex 生图、4K 渲染）也会发通知，处理方式一样：看结果文件，记台账。

## 8. 跨章验收与第二轮

全部交齐后主控做三件事：

- **首尾帧拼图**：每段取 `0.05 0.35 末尾-0.45 末尾-0.02` 四帧（`--scale=0.25`，9 段并行渲），看段首 0.5s 内有内容入场、段尾淡到空舞台、相邻段风格一致。
- **逐段 final-sheet 对照 BRIEF 量化标准**：有效字高、主体占宽、标题被裁、安全区、留白过大、只有一行字的空镜。
- **跨章去重**：同一页面状态/同一交互（如“填表 → 点开始”）只允许一章完整演示，其余章最多 2–3 秒快推或换角度。第 3 期 seg1、seg3、seg4 都演了一遍填表，seg3、seg5 都演了粘贴提示词，是审片才抓出来的——现在要在 BRIEF 的镜头归属表里提前分好，这一步只是复核。

第二轮消息用 [prompts.md](prompts.md) 的「定点修改」模板（模板里已嵌入验收清单的关键几条）：先给一句具体的肯定和预计时长，再列**全片统一的量化规则**（所有 agent 收到同一段文字），然后编号列本章的问题，每条带时间点、问题、量化的改法。只发给有问题的章节。第 3 期第二轮的规则是“放大后有效字高 ≥28px、小标签 ≥24px、主体占画面宽约 70%、被念到的标题离上沿 ≥60px”——这些现在已写进 BRIEF 模板，第二轮通常会小很多。

## 9. lib 变更协议

- **一轮进行中 lib 冻结。** 改 lib 会改变所有正在自检的段的画面，它们的拼图和预览立刻作废；改到一半还可能让别人的打包报错。
- 例外：只影响声音的参数放在 `src/data/mix.json`，随时可调（第 3 期在 9 个 agent 跑第一轮时调过音效基础音量和峰值提前量，没有影响画面）。
- **什么时候改**：只有跨章共性问题才动 lib，且等所有 agent 停下。第 3 期审片发现“两个字多的镜头叠化出现半透明双重字”出现在 4 段里，主控把 `Shot` 的 fade 改成“先离场、再进场”，在第三轮消息开头告诉所有 agent，并提醒“私有组件里自己写的交叉叠化也照这个思路改”。
- **agent 提的“收编”需求**（`FlipCard`、`Lockup`、`PageLift`……）项目中途一律不收：私有实现已经能用，收编会改动别人的画面。项目结束后挑反复出现的需求进模板（本模板已收：`Shot.outDur`、`Window.layerDur`、地址栏打完光标消失、`Pointer.ripple`、`Flowing` 默认不发光、`Strike` 默认墨色）。
- v2 的做法是边跑边改：主控修了 FX 库三个 bug，拷进 4 份副本，再用 SendMessage 通知“重新构建即可生效”。消息会在 agent 下一次工具调用时送达，能用，但每个 agent 都要重做自检。能等就等。

## 10. 独立审片与第三轮

- 时机：第二轮全部回来、预览全部重渲之后。
- 新开一个通用 agent，**干净上下文**；输入只给：带口播的预览 `out/preview/*.mp4`、`src/data/timing.json`、`BRIEF.md`、`~/.claude/skills/video-shotcraft/references/aesthetic-rules.md` 和 `final-review.md`、[qa.md](qa.md) §4 的审片维度、用户的原始要求和历次否定原话。**不给制作理由、修改历史和你的结论**（final-review 的原则：审查者不该听辩解）。
- 输出要求：总体结论 ≤3 句（能否交付 + 最大的 3 个风险）；问题清单每条 `[严重/中/轻] segN @时间 — 问题 — 改法`，只列在帧上确认过的，≤25 条；3–5 个应该保留的优点。8 个维度是检查提纲，不强制打分（分数会被刷好看，第 3 期有效的是问题清单）。
- 第 3 期审片抓到 22 处，都是制作者看不见的：跨章重复演示、模拟操作和真实报告矛盾、两张纯文字标题卡像 PPT、叠化双重字、编造的出处（“评论区 · 观众朋友”）、同一数字三种口径。
- 主控分拣：共性问题自己改 lib（等全员停下）；其余按章拆成第三轮消息；“轻”的也照改（每条 2–5 分钟）。审片不复审——第三轮回来后主控抽查改动最大的几帧即可。

## 11. 资源分配

第 3 期机器 18 核 / 64GB，9 个章节 agent 同时跑没有卡顿，配额是：

| 谁 | 配额 |
|---|---|
| 章节 agent 并发 | ≤ CPU 核数 / 2（16GB 内存的机器 ≤4）；超出就排队补派 |
| 静帧 | 一次 ≤14 帧，默认 `--scale=0.5`；推近处单独几帧 `--scale=1` |
| 预览 | 960×540、`--conc=2`；第一轮最多 2 次，修改轮 1 次；同一 agent 不并行开两个预览 |
| 主控 | 第一、二轮期间只做轻活（配乐、音效、写预览页）；首尾帧检查用 `--scale=0.25` |
| 4K 终渲 | 用 `scripts/queue.sh` 排队渲：验收过一段就往 `out/render-queue.txt` 追加一段，单进程逐段渲，每段还要补一条无配乐音轨。没有 agent 在跑时 `--conc=10`；有 agent 在渲预览时 ≤6（第 4 期 4K 用 8 并发时，agent 的预览慢了 1.3–1.9 倍）。第 3 期 6 分 03 秒全片实测 41 分钟；第 4 期 6 分 55 秒 14 段排队约 37 分钟，单段 84–229 秒。审片期间就可以先渲不会改的段 |

## 12. 台账、（可选）git 与断点续跑

- `out/ledger.json`（`$S/scripts/ledger.py --project $P …`）：每段的 agent ID、轮次、状态、一句备注；审片 agent 也记。每次派发、收稿、续派后更新。上下文压缩后第一件事是 `ledger.py show`。别 `rm -rf out`。
  这是**预防**：第 3 期对话一共压缩过 4 次，但 v3 派工到交付这段恰好没压缩；一旦压缩发生在两轮之间，丢了 ID 就只能重派（一章第一轮 25–33 万 token）。成本几乎为零，所以必做。
- （可选）`git log`：每轮一个提交（“派发前”“R1 收齐”“R2 收齐”“审片修订”“打码”），出问题时按段回滚：`git checkout <提交> -- src/segs/Seg3.tsx src/segs/seg3`。章节 agent 不碰 git。
- agent ID 丢了（或 agent 反复失败）：用 prompts.md 的「接手」模板新开 agent，让它先读 BRIEF、现有代码、最新拼图和 `out/reports/` 里的未解决问题，再按问题清单继续。

## 14. 反模式

- 样板没立就派发，或者先派发再定 tokens/lib。
- 用 fork 派章节 agent；给章节 agent 整段对话历史。
- 每人一份工程副本再合并。
- 在通知到达前向用户描述 agent 结果；读 agent 的 output 文件看进度。
- 一轮进行中改 lib 的画面行为。
- 修改意见写成“更有质感一点”——没有时间点和数字，agent 会大改结构。
- 第一轮就让审片 agent 看（制作还没稳定，审片会被大量低级问题淹没）。
- 预览发布后还在改代码却没重渲预览（`preview_page.py` 会按修改时间报警）。
- 用户提了一处修改就 `rm -rf out/final` 全片重渲——先跑 `affected.py`（第 3 期两次 `rm -rf out/final` 全片重渲，第二次跑满 41 分钟；用户最后只要求给二维码打码，真正受影响的只有引用那几张图的段）。
- 对子 agent 写“用户认可这个方向”而用户其实没看过（第 3 期 v2 真实发生，整版作废）。
- 替用户加码：用户只说“别露名字”，派单写成“名字和 logo 都不露”（第 4 期 v3 被否）。
- 做一个脱离口播的“三种镜头”样板给用户看（第 4 期 v1 被否），而不是直接做真正的第一章。
- 第一章认可后，还拿总纲、数据口径、字幕专名去问用户（用户：“不要问我了”）。
- 派发后空等通知，不巡检；会触发权限确认的命令没在 BRIEF 里禁掉。
- 主控改了 lib 却没重渲已交稿段的预览，审片看的是旧预览。
