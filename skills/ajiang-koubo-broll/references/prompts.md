# 提示词模板

`{…}` 是要填的空。模板来自第 3 期 v3 实际发出的提示词，按教训改过：去掉写报告文件、量化标准前置、加镜头归属和资源上限、把验收清单直接嵌进修改模板。

**写任何提示词前的一条铁律：只转述用户真说过的话。** 用户没看过的东西不写“用户认可”；主控自己的判断写成“总控定的”。v2 四份派单写了“风格样板……主控做的，用户认可这个方向”，用户其实没看过，整版作废。

**第二条铁律：不替用户加码。** 用户原话逐字放进引号；主控自己的推断另起一行，写成“总控推断：…”。分析 agent 回来的建议，先对照主旨和悬念表再用。
- 第 4 期：用户只说了“别把模型名称露出来”，派单写成了“不能露出模型名称和 logo”，还加了一句“讲解片，能量中低”。
- 选卡 agent 照这个建议“第一章禁止选手面板、名牌、品牌色”，v3 照做后被否：“完全没有那种大片的感觉……Logo 也没有用”。

**第三条：命令写法避开权限确认。** 派单里写明：不要用 `rm -f $D/*.jpg` 这类“变量加通配符”的删除，清目录用 python（`shutil` / `glob`）。
- 第 4 期 seg8、seg12 各卡在一条这样的命令上约 6 小时：用户在睡觉，确认框没人点。
- 另外两个环境坑也写进派单：ffmpeg 没有 drawtext（拼图标签用 PIL 画）；macOS 没有 `timeout`。

## 1. 章节 agent · 第一轮（一条消息里并行发出全部）

Agent 参数：`description: "{segN} {章节标题}"`，`subagent_type: general-purpose`，不用 fork。

```
你是 {期名} B-roll 的章节负责人，负责 **{segN}「{章节标题}」（{时长}s）**。总控（我）已经搭好工程、组件库、第一章（seg0，即风格样板）和美术总纲（用户看过第一章并说“{原话}”——只写用户真说过的原话）；另外 {N-1} 个 agent 在并行做其它章节，最后首尾相接成一支同一主题的片子。

工程目录：`{工程绝对路径}`

按顺序做：
1. 完整读 `BRIEF.md`（美术与制作总纲，所有硬约束和量化标准都在里面），再读 `src/lib/` 全部文件（组件 API）、`src/segs/Seg0.tsx`（第一章，也就是用户认可的风格样板：照这个主题、组件和尺度做，不缩小、不另起风格）、`{skill目录}/assets/examples/` 里本期同类范例的通过版和被否版拼图（ep3：浅色产品演示；ep4：深色比赛横评。用 Read 看，知道“好”“过度包装”“没有大片感”各长什么样）、`src/data/timing.json` 里 {segN} 的字幕，`{稿子路径}` 里对应段落的【画面】提示。
2. 读你的主角卡：{卡1 路径全文} + `{demo1 目录}` 的 TSX 全文{；可选 卡2}；再读 `~/.claude/skills/video-shotcraft/references/aesthetic-rules.md`。照搬卡的动作语法、时值配比和缓动（demo 是 30fps 帧数：秒 = 帧 / 30），按本片 tokens 重新蒙皮：{这张卡要去掉的东西，如“不要暗场和扫描光带，保留取景框依次咬合 + 机器标签”}。
3. 写 `src/segs/{SegN}.tsx`（私有组件放 `src/segs/{segN}/`，自己裁的图放 `public/{segN}/`），按 BRIEF 第 8 节 {segN} 的节拍设计镜头。所有时间用 `say('{segN}', …)` / `cue()` 锚到口播。
   本章专属要求：{真实素材怎么用、必须讲清的 2–4 个信息点、隐私裁切范围、语气（如“打包票让人放心，用绿/蓝，不要红色恐吓”）}。
   镜头归属：{本章完整拥有的页面状态/交互}；{别的章拥有、本章只能 2–3 秒带过或换角度的东西}。
4. 自检：`node scripts/still.mjs {segN} <秒…> --tag=vN` 看拼图，至少 3 轮，每轮自己挑毛病（构图、留白、字号、安全区、节奏、像不像同一套设计）；推近处用 `--scale=1` 看清晰度；转场重叠窗口正中、段尾最后两帧必看。做完渲一次 `node scripts/preview.mjs {segN} --conc=2`，用 ffmpeg 按口播关键词抽帧核对音画。交稿前过一遍 BRIEF 第 9 节的自检清单。
5. 交付：`src/segs/{SegN}.tsx`（+ 私有目录）`npx tsc -p .` 不报你文件的错、能渲；`out/qa/{segN}/final-sheet.jpg`（覆盖整段，每个镜头至少 2 帧）；`out/preview/{segN}.mp4`（带口播）。

命令写法：清目录用 python，不要写 `rm -f $D/*.jpg` 这类变量加通配符的删除（会触发权限确认，没人点就卡死）；ffmpeg 没有 drawtext，拼图标签用 PIL；macOS 没有 `timeout`。
规矩：只改你自己的文件（上面列的三处）；不要改 `src/lib/`、别的段、entries、scripts、`public/` 其它目录——lib 缺东西就在私有目录里写或复制改，回报里说明。不要发布 Artifact，不要跑 ego-browser 或联网截图，不要渲 4K，不要跑 git 提交或回滚（版本由我管）。临时文件只放 `out/tmp/{segN}/`。不要写报告类 .md 文件（会被系统拦），报告放在最终回复里。
机器上同时有 {N} 个 agent 在渲染：静帧一次别超过 14 帧，预览最多渲 2 次、`--conc=2`。

最后用中文回复，按这五块：① 交付文件路径 ② 镜头表（每行 `起–止秒｜画面｜转场｜主角卡或真实素材`）③ BRIEF 第 9 节清单逐条 ✓/✗（不达标写实测值）④ 遗留问题和需要我拍板的 ⑤ 对 lib 的需求。
```

## 2. 定点修改（第二轮 / 第三轮，SendMessage 续派同一个 agent）

`to:` 填台账里的 agent ID，`summary:` 写“segN 第 K 轮定点修改”。

```
{segN} 第 {K} 轮（来源：{总控验收 / 独立审片}）：只做下面几处定点修改，不动结构，大约 {10–20} 分钟。总控已经看过你的 final-sheet，{一句具体的肯定，如“报告卡四块咬合做得很好”}。
{如有 lib 变更：lib 改动：`Shot` 的 fade/zoomIn/zoomOut 改成先离场、后进场，不会再出现双重字。私有组件里如果自己写了交叉叠化，也照这个思路改。}
全片统一验收标准（所有 agent 收到同一段，改完逐条自查）：
- 想让观众读的字，放大后有效字高 ≥28px、小标签 ≥24px、眉标 ≥26px（拼图上量到的字高 ×2 = 有效字高）；
- 主体至少占画面宽约 70%，不许一小团 + 大片留白；
- 被念到的标题放 Cam 外的屏幕层，完整、离上沿 ≥60px；头像圆和字幕行里没有要读的字（推近时页面长句会滑进头像区）；
- 转场重叠窗口正中那一帧没有两层字半透明叠在一起；最后 2–4 帧是纯空舞台；
- MG 卡片叠在页面上，四周不露被截断的半截字；纯文字标题卡 ≤3s；不整屏压暗；不写死颜色；
- 数字、型号、口径和 BRIEF 第 5 节一致，模拟操作和真实产物一致，不编出处。
本章问题：
1) [{严重/中/轻}] {时间点}：{问题，说看到了什么}。{改法，带数字：放大到约 80% 画面宽 / 字高 ≥32px / 提前约 0.8s / 停 ≥1s}。
2) …
{跨章协调写清楚分工：“seg3 保留完整的逐字填表教学，你这段改成 2–3 秒粘贴带过”。}
{审片列的“做得好”原样转过来：“这几处保留，别改掉：…”}
做完重出 `out/qa/{segN}/final-sheet.jpg`，预览渲一次（--conc=2），回复 {60–100} 字以内说改了什么、实测值。
```

写法要点：每条都有时间点和数字；给两种改法时说“任选其一”；涉及别的章就说明谁保留什么；不要说“再精致一点”这类无法验收的话。

## 3. 独立审片 agent（新开，干净上下文）

```
你是这支片子的独立审片人，没参与制作。请对一支 {N} 段的 B-roll 做交付前终检，只出报告，不改任何文件，不继续委派。

工程目录：`{工程绝对路径}`

背景：这是一支约 {时长} 口播视频（{一句话主题}）的整屏画面层。用户会把它盖在口播上，自己在右上角叠小圆头像 {SAFE.avatar}、底部叠字幕 {SAFE.subtitle}（1920×1080 坐标）。用户的原始要求：{原话}。历次否定：{v1/v2 原话，若有}。

审片材料：
- 带口播的预览：`out/preview/seg0.mp4` … （960×540，{fps}fps）
- 字幕时间：`src/data/timing.json`（每段字幕原文和起止秒）
- 美术总纲：`BRIEF.md`
- 审美准则：`~/.claude/skills/video-shotcraft/references/aesthetic-rules.md`
- 终检方法：`~/.claude/skills/video-shotcraft/references/final-review.md`

怎么审：
1. 每段用 ffmpeg 每 1.5 秒抽一帧，再加你认为关键的时刻，拼成联系表用 Read 看；需要时抽音频看音效位置。临时文件只放 `{审片临时目录}`。
2. 逐段对照字幕：画面是否和口播内容对得上、时机对不对。
3. 按 final-review.md（只用 P/F/V/D/Q 和适用的 A 项；本片不是卡拍发布片，A3/A4 不适用）、aesthetic-rules.md 和下面 8 个维度逐条查（维度是检查提纲，不用打分）——讲清楚、真实感、统一、克制与质感、运镜与转场、可读与安全区、节奏与对位、事实与隐私。具体看：讲没讲清楚、真实网页是不是主角、推拉和转场是否自然、全片视觉是否统一、字是否太小（按 1080 计，要读的字 ≥24–28px）、标题有没有被裁、安全区里有没有要读的字、**跨段有没有重复镜头或重复演示**、事实和数据有没有编造或前后矛盾、有没有过度包装（发光、爆炸、抖动）、段首段尾是否干净（每段结尾淡到空舞台）、叠化时有没有双重字。
4. 不要求像素完美，抓用户一眼就会不满意的问题。

输出（中文，直接作为最终回复，不写文件）：
- 总体结论 ≤3 句：能否交付、最大的 3 个风险。
- 问题清单，每条一行：`[严重/中/轻] segN @时间s — 问题 — 建议改法`。只列在帧上确认过的，按严重程度排序，≤25 条。
- 3–5 个做得好、应该保留的地方。
```

## 5. 给用户的闸门消息

