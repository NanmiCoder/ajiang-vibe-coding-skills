# 验收：样板检查、拼图检查、整片衔接、独立审片

第 3 期的质量是一轮一轮磨出来的：

1. 章节 agent 自检 3–6 轮；
2. 主 agent 验收拼图，第二轮群发修改意见（主要是字号和构图）；
3. 独立审片 agent 挑出 22 处问题；
4. 第三轮修完，用户才说“真的非常棒”。

**不要指望一轮做完。** 规则是：首检永远不交给用户（shotcraft P1、第 8 条）。

## 0. 怎么看帧（所有检查共用）

- **出拼图**：
  - 静帧：`node scripts/still.mjs segN <秒…> --tag=x`，出来的拼图画了头像圆和字幕行两个红框；
  - 预览视频：`python3 $S/scripts/contact.py --project $P out/preview/segN.mp4 --every 1.5`（带时间戳和安全区框）。
- **挑哪几帧**：每个镜头看三帧：入场到一半、动作峰值、落定后 0.5 秒。再加上 `say()` 关键词前后各一帧，转场重叠窗口正中一帧（双重字就出现在这里），段首 0.05 / 0.35 秒，段尾 −0.45 / −0.02 秒。
- **量有效字高**：拼图是 960 宽，1920 设计坐标折半显示。所以拼图上量到的字高 × 2 = 设计坐标里的有效字高。拿不准就用 `--scale=1` 单出那一帧，再裁出来看。
- **全片统一**：所有段的首帧、尾帧和每段一张代表帧放在一张图里看。不同 agent 做的段，放在一起要像同一个人做的。

## 1. 第一章自检（发给用户之前，主控自己过至少两轮）

第一章就是风格样板，用户看过它就决定了全片。第 4 期第一章交了 4 版，每一版被否的原因都对应下面某一条。

**对位与真实**
- [ ] 每句口播都有画面落点：按口播关键词每句抽一帧，对照预览确认音画同步。第 4 期 v1：“你的音频完全没有跟画面一起走”。
- [ ] 画面形态按句子选：真实动画、截图推近、录屏、MG 各用在该用的句子上，不是句句截图（[chapters §3.5](chapters.md)）。
- [ ] 产品自己用前端画的动画，已经移植并用真实数据驱动，没有拿录屏或截图冒充。
- [ ] 有真实数据就没有示意图表。

**主题与大片感**（[art-direction §0](art-direction.md)）
- [ ] 用了产品自己的主视觉、立绘、动画组件，主题能用一句话说清（“产品自己的 X 舞台 + Y 式演出”）。
- [ ] 舞台不空、字和数字够大（主标题 120–170px、关键数字 200–470px）、实物有体积、至少一个产品原生的演出组件。
- [ ] 至少用了 2 张 video-shotcraft 卡的动作语法。
- [ ] 第一眼像不像这个产品自己出的片子：把产品官网截图和第一章帧并排放，看色、字、圆角、阴影是不是同一家。

**悬念、logo、口径**
- [ ] 悬念只藏本期的名次和身份；前几期的榜照常放。
- [ ] 口播点名的模型都有 BrandMark；没揭晓的身份位用 logo 老虎机停在“?”。
- [ ] 画面上没有和口播矛盾的数字（第 4 期 seg0 魔方榜分数 99.6 和口播“七八十分”同屏，漏查）。

**基本功**
- [ ] 真实页面镜头：推到位后，要讲的那块占画面主体，字够大，不糊（看 art-direction §3 的放大倍数）。
- [ ] 标题在 Cam 外，推拉时不会被裁，标题下面不压截图字。
- [ ] 没有写死的颜色（取截图像素的页面补丁除外）。
- [ ] 没有禁用项：我们自己加的发光、粒子、震屏、整屏压暗。
- [ ] 段首 0.3 秒内有东西入场；背景从空舞台淡入；段尾淡到空舞台。

## 2. 章节验收清单（每个 agent 交稿后，主 agent 看 final-sheet 和预览）

**讲清楚**

- [ ] 关掉声音只看画面和字幕，能复述这段讲了什么吗？每个关键句都有一个画面落点吗？
- [ ] 画面和口播说的是同一件事、同一个词吗？有没有画面在讲上一句或下一句？

**真实感**

- [ ] 页面上有的东西用的是真实截图吗？有没有手搓了一个本来可以截的界面？
- [ ] 产品自己用前端画的动画，用的是移植版加真实数据吗？有没有拿录屏或手画冒充？
- [ ] 本段至少有一处真实页面或真实产物落点吗？纯原理段也要有一处，比如页面原文的一句声明。

**可读与构图**

- [ ] 要读的字有效字高 ≥ 28，小标签 ≥ 24，眉标 ≥ 26。
- [ ] 主体占画面宽度 ≥ 70%，没有“一小团加大片留白”。
- [ ] 正在被念到的标题完整，离上沿 ≥ 60，没被推拉裁掉。
- [ ] 截图推近时，标题下面没有压着页面字。标题区 y<150 要给截图加渐变压暗，或者取景下移；第 4 期 seg3/4/11/13 都出过双重字。
- [ ] 主体也不能太大：不贴边、不被裁（第 4 期推近后右侧生命条被裁掉）。用户原话：“不要太小 也不要太大”。
- [ ] 标题的可见时长 ≥0.5 秒。口播两句挨得很近时，`Lines` 会把前一句吞掉，合并成一条，或者给前一句写 `end`。
- [ ] 头像圆和字幕行里没有要读的字。注意镜头推近时，页面里的字会滑进头像区（第 4 期 seg8 板头步数挤进了头像圆）。
- [ ] MG 卡片叠在页面上时，卡片四周没有露出被截断的半截字，比如“开始检”“答粘贴回”。要么页面压一层淡纱，要么卡片落在页面空白处。

**统一与克制**

- [ ] 只用了 tokens 里的颜色；结论色只表示结论。
- [ ] 转场 ≤ 3 种，按两镜关系选。
- [ ] 没有整屏压暗。第 3 期 seg4 用全屏灰罩做聚光，是全片唯一一处这样做，审片判为手法不一致。
- [ ] 没有纯文字标题卡超过 3 秒。第 3 期 seg5 连续两张标题卡加起来约 11 秒，审片说“像 PPT”。

**节奏**

- [ ] 关键信息比口播早 0.1–0.3 秒或同时出现，没有晚 1 秒以上的。
- [ ] 落定后停 ≥ 1 秒。
- [ ] 计数、翻牌类动作在口播说完那个数字时到位。第 3 期 seg5：口播“8 次真 Opus”说完时，画面只翻了 6 张。

**事实与隐私**

- [ ] 数字、型号、排名和截图、口播一致，按 BRIEF 第 5 节的口径表写。
- [ ] 有真实数据的地方没有示意图表。
- [ ] 画面上没有和口播矛盾的数字：画面跟口播走，矛盾的那一列要裁掉或压暗。
- [ ] 状态用词和用词表一致，如“超时 / 调用失败 / 安全拦截”。
- [ ] 悬念揭晓前，没露出本期名次、总分、花费（包括截图角落里的数字）。
- [ ] 没有编出的出处或数字。
- [ ] 没有二维码、邮箱、Key、费用、内部后台。

**跨段**

- [ ] 同一个操作、同一段回放、同一张整页截图，只完整演示一次。第 3 期“填表 → 点开始”在 seg1、seg3、seg4 各演了一遍；第 4 期魔方榜整页出现了 3 次。
- [ ] 同一种手法只当一次主角。

## 3. 整片衔接（全部交齐后）

```sh
# 每段首尾帧（秒数从 timing.json 读），--scale=0.25 并行渲
for k in $(python3 -c "import json;print(' '.join(json.load(open('src/data/timing.json'))['segments']))"); do
  e=$(python3 -c "import json;print(json.load(open('src/data/timing.json'))['segments']['$k']['seconds'])")
  node scripts/still.mjs $k 0.05 0.35 $(python3 -c "print(round($e-0.45,2), round($e-0.02,2))") --tag=ends --scale=0.25 &
done; wait
```

- [ ] 每段第 0.3–0.5 秒内容已经入场，没有长时间空舞台；段中也没有超过 1 秒的空舞台（第 4 期 seg1、seg11 各有 1.3–1.5 秒）。
- [ ] **段首接缝亮度**：上一段末帧和这一段首帧的平均亮度差 ≤3（`check.py` 会查）。第 4 期 seg6/7/11 第 0 帧就是亮舞台（亮度 23–26），上一段末帧约 10.8，剪映里会闪一下；改成背景 0.3–0.5 秒淡入。
- [ ] **跨段重复**：同一段回放、同一张整页截图，只在一章完整出现（第 4 期：MiniMax 第 1 关推死放了两遍，魔方榜整页出现 3 次）。对照 BRIEF 的逐句镜头表查素材键。
- [ ] 每段最后 2–4 帧是纯空舞台，没有残留 5–10% 的内容。第 3 期 seg1、seg7 都残留过，接下一段会跳一帧。
- [ ] 相邻两段的“上一段尾帧”和“下一段首帧”是同一张舞台。
- [ ] `npx tsc -p .` 通过；预览 mp4 比源码新（`stat` 比较时间），不能拿旧预览给用户看。

## 4. 独立审片（交付前，必须是干净上下文的新 agent）

**为什么必须做：** 制作者对自己的作品有确认偏差。第 3 期主控验收两轮之后，独立审片仍然挑出 22 处：

- 2 处前后事实矛盾（两次 vs 三次探针、同一数字三种口径）；
- 3 处重复镜头（填表演三遍、粘贴提示词演两遍）；
- 双重字（4 段）；
- 编造的出处；
- 段尾残留；
- 标题卡像 PPT。

**派法：** 通用 agent，只给材料和标准，**不给制作过程中的理由、辩解和修改历史**；只出报告，不改文件。提示词原文见 [prompts.md](prompts.md) §3。时机：第二轮全部回来、预览全部重渲之后（太早会被低级问题淹没）。

### 8 个审片维度（检查提纲，不强制打分）

分数会被刷好看，第 3 期起作用的是“问题清单 + 保留清单”。维度用来保证不漏看：

| 维度 | 好的样子 | 坏的样子 |
|---|---|---|
| **讲清楚** | 静音只看画面加字幕也能复述内容；每个关键句都有画面落点 | 画面是装饰，和口播各说各的 |
| **真实感** | 能截的都截了；真实页面占画面主体；MG 从页面里长出来 | 手搓的假界面代替真页面；截图缩成小窗当点缀 |
| **统一** | 各段像同一个人做的：同一张舞台、同一个强调色、同一套组件和镜头语言 | 各段各有一套配色、字体或转场 |
| **克制与质感** | 没有禁用特效；包装体现在运动上（错峰、抬起、咬合、马克笔）；每帧都精致 | 粒子、发光、震屏、印章；或者反过来，全是静态 PPT 页 |
| **运镜与转场** | 推拉像真人演示，推到位就停；转场按关系选；没有双重字；段与段无缝衔接 | 推个不停、抖动、乱倾斜；叠化重影；段尾跳帧 |
| **可读与安全区** | 要读的字 ≥28 / 24；主体饱满；头像区和字幕区干净 | 字小得看不清；标题被裁；字压在头像上 |
| **节奏与对位** | 关键信息早 0.1–0.3 秒到位，停 ≥1 秒；4–8 秒推进一次；没有超过 3 秒的空画面 | 画面晚于口播；刚出来就走；长时间不动或一直在动 |
| **事实与隐私** | 数字、名称和截图、口播一致；画面不露和口播矛盾的数字；没有示意图表；悬念没提前泄露；隐私已打码 | 编数字或出处；前后矛盾；露出二维码或后台 |

### 怎么处理审片结果

- **有任一 `严重`**：必须修，修完主控亲自抽查那几段的关键帧（不再起第二个审片 agent）。
- **`中`**：本轮全部修。
- **`轻`**：修起来便宜的就修（第 3 期审片列出的 22 条，第三轮全部修了）。不修的写进交付说明。
- **所有段共有的问题**（例如双重字），由主控等所有 agent 停下后在 lib 里统一修一次，见 [orchestration.md](orchestration.md) §9。各段自己的问题，按章节 SendMessage 分派（[prompts.md](prompts.md) §2）。
- **“做得好”的条目**原样转给对应章节，叮嘱“保留”。

### 严重程度的定义

- **严重**：用户一眼就会否掉，或者发出去会出事。比如方向错（过度包装、截图不是主角）、事实错误、隐私泄露、某段渲不出来、段与段之间有空档或重叠。
- **中**：影响理解或看起来明显不精致。比如关键信息晚了 1 秒以上、重复镜头、前后矛盾的小数字、长时间纯文字、要读的字明显太小。
- **轻**：细节，比如单处字号差 2–4px、某帧残留、某个转场方向不顺。
