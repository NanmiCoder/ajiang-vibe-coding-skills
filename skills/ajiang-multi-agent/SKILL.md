# 多 Agent 模式选择：Sub-agent vs Agent Teams / 蜂群

核心原则：**默认用单会话 Sub-agent；只有横向协作或独立深挖的收益明显大于协调与 Token 成本时，才上 Agent Teams / 蜂群。**

## 三问快速决策

接到复杂任务后，先过这三问：

1. **成员之间需不需要互相通信、质疑或协商契约？**
   - 各自干完只需把结果交回主 Agent → **单会话 Sub-agent**
   - 需要彼此对齐接口、互相挑刺、交叉验证结论 → 倾向 **Agent Teams / 蜂群**
2. **文件所有权和执行顺序能不能切干净？**
   - 步骤强串行（下一步依赖上一步结果），或多人会改同一批文件 → **单会话 Sub-agent**（甚至单 Agent 顺序完成）
   - 不同目录、模块或视角完全独立，各自需要干净上下文 → 满足 **Agent Teams / 蜂群** 的前提
3. **并行与隔离收益是否明显大于协调和 Token 成本？**
   - 路径清晰、十几分钟能做完的聚焦任务 → **单会话 Sub-agent**
   - 跨层并行开发、多角度交叉审查、多假说竞争排障、大批量可分片交付 → **Agent Teams / 蜂群**

**判定规则**：第 2、3 问不满足时，一律不要上 Teams / 蜂群；三问同时满足，或存在大量互相独立的分片需要并行交付且各片需要独立上下文时，启用 **Agent Teams / 蜂群**。

## 场景速查表

| 场景 | 推荐模式 | 原因 |
|---|---|---|
| 代码库检索、资料调研、单点排查 | **单会话 Sub-agent** | 只需回报主 Agent，无需成员间通信 |
| 顺序流水线（先改库→再写接口→再联调） | **单会话 Sub-agent** | 强先后依赖，并行空等浪费成本 |
| 单文件或紧耦合模块修改 | **单会话 Sub-agent** | 并发改同一文件必然覆盖冲突 |
| 一次性只读代码审查 | **单会话 Sub-agent** | 独立上下文审完交回主 Agent 即可 |
| 跨层并行开发（前端 / 后端 / 测试） | **Agent Teams / 蜂群** | 目录隔离，先对齐接口契约再并行交付 |
| 多角度交叉审查（安全 / 性能 / 测试） | **Agent Teams / 蜂群** | 独立深挖后互相质疑，减少盲区 |
| 疑难 Bug 多假说竞争排障 | **Agent Teams / 蜂群** | 多路并行验证假说，用证据互相证伪 |
| 大批量独立分片并行（按模块/章节/文件） | **Agent Teams / 蜂群** | 上下文互不污染，总耗时显著缩短 |

## 执行守则

### 选单会话 Sub-agent 时

- 主 Agent 先整理中立、完整的上下文（目标、文件路径、约束、期望交付格式），不要只扔一句模糊指令。
- 互相独立的只读调研或隔离验证可并行派发多个 Sub-agent，结果统一由主 Agent 核实并汇总。
- 避免让多个 Sub-agent 同时写入同一份正式代码。

### 选 Agent Teams / 蜂群时

- **控制规模**：2–4 个成员最优；超过 5 人协调开销与 Token 消耗会急剧上升。
- **锁定文件所有权**：每个成员只改自己负责的目录或文件集；跨层任务先定好接口契约再分头实现。
- **给足独立上下文**：成员默认不继承主会话历史，派发时必须写明背景、边界、负责路径和完成标准。
- **主控只协调不抢活**：主 Agent 负责拆任务、盯进度、解阻塞、核实发现与综合结果，不一边派人一边自己改同一块代码。
- **按证据收敛并及时收尾**：成员间讨论以代码、日志和实测结果为准，不靠刷消息凑共识；任务验收完成后及时关闭成员并清理临时工作区或任务状态。

使用当前环境提供的 Sub-agent、Agent Teams 或蜂群能力，不限定特定客户端、模型或工具名。若当前环境不支持 Teams / 蜂群或成员间通信，明确告知限制，降级为单会话 Sub-agent 串行或独立分片执行。

## 输出格式

每次做模式决策与编排时，按三段简洁输出：

1. **模式选择与理由**：明确选「单会话 Sub-agent」还是「Agent Teams / 蜂群」，用三问给出依据。
2. **拆分方案**：列出角色或子任务、各自负责的文件/目录边界、需要对齐的契约或交接点，以及验收标准。
3. **风险与降级**：指出潜在文件冲突、Token 成本控制点，以及何时收敛或降级回单会话。

复杂多成员任务可用 [多 Agent 编排记录](assets/task-record.md) 跟踪分工、文件边界与验收结果。
