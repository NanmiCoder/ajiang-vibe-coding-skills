# 交付

## 文件

每段一个 MP4：
- 母版分辨率和帧率，H.264 CRF 16，bt709；
- **帧数严格等于区间长度**；
- 音频只有配乐加音效，**不含口播**（口播留在用户时间线原来的音轨上），整体比同区间口播低 16 dB，真峰值 ≤ -14 dBFS；
- 不另附 WAV 分轨（用户已经定了）。

## 命名（硬约束）

用户要靠文件名直接在时间线上卡位，所以文件名必须能对上 SRT：

```
{序号}_{标题}_{SRT起点}~{SRT终点}_字幕{首条}-{末条}.mp4
2_Case02在线Excel引擎_00-03-53,967~00-04-47,267_字幕103-132.mp4
```

- 时间和 SRT 是同一条时间轴，精确到毫秒。macOS 文件名不能用冒号，`:` 换成 `-`，逗号后面是毫秒。
- 时间按帧换算，所以会出现 `,967` 这种不整的毫秒数，这是对的。
- 区间是左闭右开：终点那一帧属于后面的原片。
- 文件名由 `srt_segments.py` 生成，写在 `segments.json` 的 `outName` 字段里，渲染脚本直接读取。**不要用帧号或英文 id 命名。**

## 替换对照表

`init_project.py` 会在工程根目录生成 `替换对照表.txt`，每段列出：
- SRT 起止时间和时长；
- `分:秒:帧` 时间码和帧号；
- 覆盖的字幕条号、首句和末句；
- 标注"这句在区间开始前已经开口 / 在区间结束后才说完"。

和成片一起交付。

## 检查并拷贝

```sh
python3 <skill>/scripts/check_delivery.py <工程目录> --copy-to "<用户的素材目录>"
```

检查项：
- 文件名；
- 帧数、分辨率、帧率；
- 有没有音轨；
- 音轨比口播低多少 dB、峰值（目标读主题的 `sound.levels`：低于口播不足 14 dB 警告、不足 10 dB 报错，峰值高于 -14 dBFS 报错）。

全部通过才会拷贝，连同替换对照表一起。拷贝目录默认 `<SRT 所在目录>/B-roll成片/`（414 期一直这样放），用户另说就按他说的。

## 交付说明（给用户的回复）

- 列出每个文件对应替换哪一段。直接给文件名就够了，文件名本身就是时间。
- 说明哪些项用脚本验证过（帧数、命名、响度），哪些项没有验证（**没有试听**）。
- 列出需要用户确认的点：措辞上有争议的地方、用评测原文补充的内容、用户之前没确认过的取舍。
- 不要贴大段代码或工程细节。
