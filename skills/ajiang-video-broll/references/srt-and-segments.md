# 读懂字幕、选段、定文案

## 1. 先读完整条字幕

```sh
python3 <skill>/scripts/srt_segments.py list --srt <视频.srt>
```

这条命令会列出每句的条号、起始帧、`分:秒:帧` 和 SRT 时间。母版视频默认取 SRT 同目录下的同名文件（`.mov` / `.mp4` 等），帧率和总帧数从母版读取；找不到母版时按 30fps 计算。

读完后先写一段 200 字以内的理解，再动手：
- 视频在讲什么，有哪些章节，各自在什么时间；
- 每个章节的结论是什么；
- 作者的整体判断；
- 出现了哪些品牌和产品（用来收集 logo）；
- 有没有对比关系（A vs B）。有对比时，固定一方在左、一方在右，和录屏分屏的左右保持一致。

## 2. 选段

**用户给了时间段时，原样使用。** 用户的写法一般是 `分:秒:帧`，比如 `03:23:06-03:32:15`，帧号按母版帧率计算。

**用户没给时，自己推荐**，在预览页里连同理由一起给用户确认。适合做包装的段落：

| 类型 | 字幕里的信号 | 时长 |
|---|---|---|
| 开场 | 第一句到"今天来看看 / 我们来测一下" | 10–20s |
| 章节结论 | "那这个 case……确实……""最后的话是……""决定排名的是……" | 8–60s |
| 数据 / 对比 | 分数、排名、消耗、价格（录屏里已经有清楚画面的就别做） | 10–30s |
| 总结 | "最后来总结一下"到推广开始之前 | 15–30s |

不适合做：
- 实操录屏段：观众要看的就是录屏本身；
- 推广口播；
- 结尾的"一键三连"。

包装总时长占全片 15–25% 比较合适。区间边界尽量落在两句之间，切在一句话中间也可以，对照表会自动标出来。

生成数据源：

```sh
python3 <skill>/scripts/init_project.py --srt <视频.srt> --out <工程目录> \
  --seg "00:00:00-00:16:00=开场" --seg "03:23:06-03:32:15=Case01耳机官网|01" ...
```

- `=标题|短名` 里的短名显示在顶部导航，可以省略。
- 已有工程重跑这条命令，只会更新 `src/segments.json` 和替换对照表，不会动源码；已经填好的 `breaks` 会保留。
- 段内换页的帧号写进 `segments.json` 对应段的 `breaks` 数组，配乐会在这些位置前停一拍，再接一个很轻的上升音。

## 3. 听写勘误

自动字幕常见的错误：
- 品牌和型号的大小写、空格：`Deepseek` → `DeepSeek`，`modeldial` → `ModelDial`，`GPT6` → `GPT-6`；
- 同音字：年会 → 年费，缓冲 → 缓存，域界 → 越界；
- 括号里的备注，比如"（不是6.1）"，不要上屏；
- 口播里的代称要换成真名：比如"天才程序员"指的是 Codex。

把勘误整理成一张"原文 → 正确写法"的表，放进预览页。**所有上屏文字一律用正确写法**。

查卡点时还是用 SRT 原文，`cueAt` 按原文匹配，听写错误也要照抄。

## 4. 上屏文案的规矩

1. **只写口播里说过的结论。** 不要自己加分数、百分比、评价。用户手头有评测原文（例如 review.md）时，可以拿来核对事实，或者补一条和口播一致的具体例子当点缀，但要在交付说明里列出来，让用户确认。
2. **提炼关键词，不抄整句**：后期还会叠字幕。
3. **力度和口播一致。** 口播说"稍微好一点"，就写"稍好 / 略胜"，不写"碾压 / 完胜"。口播的说法和评测原文冲突时，选两边都不冲突的说法（比如写"更完整"而不是"更正确"），并在预览页标出来。
4. 卡点用每句话的**开始帧**；元素至少停留到这句说完，再加 15 帧。
